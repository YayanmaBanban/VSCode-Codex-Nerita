近いですが、**同じ仕組みではありません**。むしろ `codex-chatgpt-web` の方が一段深く、**ChatGPT Web を「Codex のネイティブモデル」に見せるブリッジ**になっています。:chatgpt-content-reference{index="0"}

|                   | `codex-chatgpt-pro-plugin`           | `codex-chatgpt-web`                           |
| ----------------- | ------------------------------------ | --------------------------------------------- |
| ChatGPTへの接続   | ブラウザ自動操作                     | ブラウザ自動操作                              |
| ブラウザ          | 外部Chrome + CDP `:9222`             | **内蔵Electron Browser**                      |
| Codexからの見え方 | `chatgpt-pro` を外部相談役として呼ぶ | **ChatGPT WebをCodexのモデルとして選択**      |
| コンテキスト      | プロンプトとして渡す                 | Codexのcompiled task contextを渡す            |
| 応答              | CLI/tool の結果として返す            | **Responses API + SSEとしてストリーム**       |
| ツール利用        | 基本は相談役                         | Full modeではCodexのtool harnessをMCPで逆接続 |
| セッション        | repo/room中心                        | **Codex task ↔ Temporary Chat**               |
| Chrome依存        | あり                                 | なし                                          |

前者は、前回見た通り専用Chrome profileを `127.0.0.1:9222` のCDPで操作します。:chatgpt-content-reference{index="1"}

一方こちらは、

```text
Codex
  │
  │ Responses API
  ▼
codex-chatgpt-web daemon
  │
  │ browser automation
  ▼
Embedded Electron Browser
  │
  ▼
ChatGPT Web
```

という構造です。CodexにはローカルのResponses互換エンドポイントを見せて、その裏側でChatGPT Webを操作しています。:chatgpt-content-reference{index="2"}

これがかなり重要です。

### 今作っているVS Code拡張には、こっちの発想の方が近い

以前考えていた方式は、

```text
Codex
   │
   └─ MCP: ask_chatgpt_pro()
              │
              ▼
          ChatGPT Web
```

でした。

これはつまり、

> 「Codexはメインモデルのまま、ChatGPT Proを相談役として呼ぶ」

方式です。

ところが `codex-chatgpt-web` は、

```text
VS Code Chat UI

Model:
 ├─ Codex / Astra
 ├─ Codex / Sol
 └─ ChatGPT Web / Pro   ← これを直接選択
```

に近い。

READMEでも、ChatGPT Webの Instant / Medium / High / Extra High / Pro を**Codexのnative model pickerから選択する**構成になっています。:chatgpt-content-reference{index="3"}

なので、あなたが以前言っていた

> VSCodeでもChatGPTモードを使いたい

に対しては、**こちらのアーキテクチャの方が目的に近い**です。

---

さらに面白いのが Full harness です。

普通にブラウザでChatGPTを開いただけなら、

```text
ChatGPT Web
   × ワークスペースファイル
   × Terminal
   × Codex tool
```

になります。

でもこのプロジェクトでは逆方向にMCPを張って、

```text
             ChatGPT Web
                  │
               MCP call
                  ▼
          OpenAI Tunnel
                  │
                  ▼
codex-chatgpt-web capability broker
                  │
                  ▼
              Codex task
              │   │   │
           files shell tools
```

という構造にしています。

つまり**ブラウザ上のChatGPT Proが、元のCodex taskのfilesystem / shell / tools / approvalsを使える**ようにしています。:chatgpt-content-reference{index="5"}

これはかなり大胆です。

---

### ただし、VS Code拡張に丸ごと移植する必要はないと思います

今のあなたの構成なら、

```text
VSCode Extension
│
├─ UI / React
│
├─ ACP Client
│    └─ codex-acp
│
├─ Providers
│    ├─ CodexProvider
│    └─ ChatGPTWebProvider   ← NEW
│
└─ BrowserBridge
     └─ VSCode Integrated Browser
          └─ chatgpt.com
```

くらいにできます。

`codex-chatgpt-web` から参考にしたいのは、

- Responses互換ブリッジ
- Codex context → ChatGPT Temporary Chat の変換
- task単位のbrowser session
- model / effort マッピング
- SSE streaming
- compaction時のセッション切り替え
- response binding / turn ID の検証

あたりです。

実際、このプロジェクトは表示順の `conversation-turn-N` ではなくChatGPT側の論理的な `data-turn-id` を使って、「今回送信した質問に対する回答か」を追跡しています。UI再描画で古いメッセージを誤取得しないためです。:chatgpt-content-reference{index="6"}

この辺はかなり参考になります。

---

そして、前回の案を少し修正したくなりました。

最終的には **2系統持つのがかなり強い**と思います。

```text
VS Code Extension
│
├─ Model Provider
│   │
│   ├─ Codex
│   │    Astra / Sol / ...
│   │
│   └─ ChatGPT Web
│        Instant
│        Medium
│        High
│        Extra High
│        Pro
│
└─ Tools
     │
     └─ ask_chatgpt_pro
```

つまり、

**ChatGPTモード**

```text
ユーザー
 ↓
ChatGPT Pro
 ↓
回答・実装
```

と、

**Codex + ChatGPTレビュワーモード**

```text
ユーザー
 ↓
Codex
 ↓
必要な時だけ
ask_chatgpt_pro
 ↓
ChatGPT Pro
 ↓
Codex
```

を両方持てる。

前者は `miuuyy/codex-chatgpt-web` 型、後者は `pauljunsukhan/codex-chatgpt-pro-plugin` 型です。

今作っているVS Code拡張なら、**この2つを同じ `ChatGPTWebBridge` の上に載せる設計**にするとかなり綺麗だと思います。

特に `codex-chatgpt-web` は現在かなり活発で、直近の v5.0.8 まで更新されているので、ブラウザDOM追従やコンテキスト受け渡しについては、前者よりこちらを主要な参考実装にした方がよさそうです。:chatgpt-content-reference{index="7"}
