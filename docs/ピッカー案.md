`ContextPicker` を追加する項目を選ぶ本体、`ContextPickerTrigger` を選択画面を開く入口として分ける案です。

```tsx
<ContextPicker>
  <ContextPickerTrigger type="button">
    <Plus />
  </ContextPickerTrigger>

  <ComposerInput />
</ContextPicker>
```

`#` 入力時は、ボタンとは別の操作経路から同じ `ContextPicker` を開きます。

```tsx
<ContextPicker
  open={contextPickerOpen}
  query={contextQuery}
  onOpenChange={setContextPickerOpen}
  onSelect={handleContextSelect}
/>
```

### `ContextPicker` の責務

検索や項目の選択に関する機能を `ContextPicker` に集約します。

```text
ContextPicker
├─ 検索
├─ 添付ファイル
├─ ファイルとディレクトリ
├─ シンボル
├─ セッション
├─ ハンドオフ
└─ Git の変更
```

使用例は次のとおりです。

```tsx
<ContextPicker
  open={open}
  query={query}
  onQueryChange={setQuery}
  onSelect={(item) => addContext(item)}
/>
```

`+` ボタンと `#` 入力のどちらから開いても、次の処理を共有できます。

- 検索ロジック
- 一覧
- キーボード操作
- 選択処理
- 最近使った項目

---

### `ContextPickerTrigger` の責務

`ContextPickerTrigger` は、選択画面を開く処理だけを担当します。

```tsx
<ContextPickerTrigger>
  <Plus />
</ContextPickerTrigger>
```

ボタンを押すと、次の処理を呼び出します。

```ts
openContextPicker({
  source: "button",
  query: "",
});
```

`variant` を持たせる場合は、次の形も選べます。

```tsx
<ContextPickerTrigger variant="plus" />
```

ただし、次の形まで抽象化する必要性は低いという見立てです。

```tsx
<ContextPickerTrigger type="button" />
<ContextPickerTrigger type="hash" />
```

`#` は UI ボタンではなく、**`ComposerInput` の入力イベント**だからです。

---

## ボタンと入力イベントの役割を分ける案

```text
Composer
├─ ComposerInput
│    └─ 「#」を検出 → ContextPickerを開く
│
├─ ContextPickerTrigger
│    └─ 「＋」クリック → ContextPickerを開く
│
└─ ContextPicker
     ├─ Search
     └─ Items
```

`ContextPickerTrigger` は `＋` ボタン専用にします。

```tsx
<ContextPickerTrigger />
```

`#` 入力時は、次のように選択画面を開きます。

```tsx
function handleInputChange(value: string) {
  const contextQuery = detectContextQuery(value);

  if (contextQuery) {
    setContextPicker({
      open: true,
      source: "inline",
      query: contextQuery.query,
    });
  }
}
```

この構成の方が、ボタンと入力イベントの役割を分けやすくなります。

type ContextPickerState = {

## 選択後の入力更新を経路ごとに変える

`source` を使うと、選択画面を開いた経路に応じて入力欄の更新を分けられます。

たとえば、＋ボタンから次の順に `App.tsx` を選びます。

```text
＋ → ファイルとディレクトリ → App.tsx
```

この場合は入力欄に、次のコンテキストチップを追加します。

```text
[App.tsx]
```

一方、次の入力から項目を選ぶ場合です。

```text
#app
```

ここから `App.tsx` を選ぶと、次の入力文字列を削除します。

```text
#app
```

削除した位置を、次のコンテキストチップへ置き換えます。

```text
[App.tsx]
```

項目を追加する共通処理は、次の呼び出しです。

```ts
addContext(item)
```

`source: "inline"` の場合は、次の処理も追加します。

```ts
removeHashQueryFromInput()
```

## コンポーネント名と分割案

次のコンポーネント名は、担当する役割を表す命名として自然だと考えます。

```text
ContextPicker
ContextPickerTrigger
ContextPickerItem
ContextPickerSearch
ContextPickerGroup
```

使用例は次のとおりです。

```tsx
<ContextPicker>
  <ContextPickerSearch />

  <ContextPickerGroup label="コンテキスト">
    <ContextPickerItem type="attachment" />
    <ContextPickerItem type="file" />
    <ContextPickerItem type="symbol" />
    <ContextPickerItem type="session" />
    <ContextPickerItem type="handoff" />
    <ContextPickerItem type="changes" />
  </ContextPickerGroup>
</ContextPicker>
```

ただし、最初からここまで細分化する必要はありません。次の2ファイルから始めれば十分です。

```text
ContextPicker.tsx
ContextPickerTrigger.tsx
```

今回の案では、**既存の `#` 用メニューを `ContextPicker` にまとめ、＋ボタンを `ContextPickerTrigger` に変更する**と、最小限のリファクタリングで済みます。
