`ContextPicker` が「何を追加するか選ぶ本体」、`ContextPickerTrigger` が「その Picker を開く入口」です。

```tsx
<ContextPicker>
  <ContextPickerTrigger type="button">
    <Plus />
  </ContextPickerTrigger>

  <ComposerInput />
</ContextPicker>
```

そして `#` 入力時は、ボタンとは別の Trigger 経路から同じ `ContextPicker` を開きます。

```tsx
<ContextPicker
  open={contextPickerOpen}
  query={contextQuery}
  onOpenChange={setContextPickerOpen}
  onSelect={handleContextSelect}
/>
```

### `ContextPicker` の責務

こちらに実際の機能を集約します。

```text
ContextPicker
├─ 検索
├─ 添付ファイル
├─ ファイルとディレクトリ
├─ シンボル
├─ セッション
├─ ハンドオフ
└─ Git の変更
```

例えば、

```tsx
<ContextPicker
  open={open}
  query={query}
  onQueryChange={setQuery}
  onSelect={(item) => addContext(item)}
/>
```

という感じです。

`+` から開こうが `#` から開こうが、

- 検索ロジック
- 一覧
- キーボード操作
- 選択処理
- 最近使った項目

は全部これを共有できます。

---

### `ContextPickerTrigger` の責務

Trigger はかなり薄くします。

```tsx
<ContextPickerTrigger>
  <Plus />
</ContextPickerTrigger>
```

押したら、

```ts
openContextPicker({
  source: "button",
  query: "",
});
```

するだけ。

もし variant を持たせるなら、

```tsx
<ContextPickerTrigger variant="plus" />
```

でもよいです。

ただし、私は前に書いた

```tsx
<ContextPickerTrigger type="button" />
<ContextPickerTrigger type="hash" />
```

まで抽象化する必要は **あまりない** と思います。

なぜなら `#` は実際にはUIボタンではなく、**ComposerInputの入力イベント**だからです。

## 実装としては、こっちの方が自然

```text
Composer
├─ ComposerInput
│    └─ 「#」を検出 → ContextPickerを開く
│
├─ ContextPickerTrigger
│    └─ 「＋」クリック → ContextPickerを開く
│
└─ ContextPicker
     ├─ Search
     └─ Items
```

つまり、

```tsx
<ContextPickerTrigger />
```

は `＋` 専用。

`#` は、

```tsx
function handleInputChange(value: string) {
  const contextQuery = detectContextQuery(value);

  if (contextQuery) {
    setContextPicker({
      open: true,
      source: "inline",
      query: contextQuery.query,
    });
  }
}
```

のように開きます。

この方が責務が素直です。

## 状態はこんな感じ

例えば、

```ts
type ContextPickerState = {
  open: boolean;
  source: "button" | "inline";
  query: string;
};
```

### ＋をクリック

```ts
{
  open: true,
  source: "button",
  query: ""
}
```

表示：

```text
コンテキストを追加

📎 添付ファイル
📁 ファイルとディレクトリ
◇ シンボル
💬 セッション
↗ ハンドオフ
± Git の変更
```

### `#sess` と入力

```ts
{
  open: true,
  source: "inline",
  query: "sess"
}
```

表示：

```text
セッション
ハンドオフ
```

となります。

## 選択後だけ少し挙動を変える

ここが `source` を持つメリットです。

たとえば＋から、

```text
＋ → ファイルとディレクトリ → App.tsx
```

なら、Composerに

```text
[App.tsx]
```

というContext Chipを追加。

一方、

```text
#app
```

から `App.tsx` を選んだ場合は、

```text
#app
```

の文字列自体を削除して、

```text
[App.tsx]
```

へ置換します。

つまり共通処理は、

```ts
addContext(item)
```

ですが、inlineの場合だけ、

```ts
removeHashQueryFromInput()
```

が追加されます。

## コンポーネント名も良いと思います

私はかなり自然だと思います。

```text
ContextPicker
ContextPickerTrigger
ContextPickerItem
ContextPickerSearch
ContextPickerGroup
```

まで発展させられます。

例えば、

```tsx
<ContextPicker>
  <ContextPickerSearch />

  <ContextPickerGroup label="コンテキスト">
    <ContextPickerItem type="attachment" />
    <ContextPickerItem type="file" />
    <ContextPickerItem type="symbol" />
    <ContextPickerItem type="session" />
    <ContextPickerItem type="handoff" />
    <ContextPickerItem type="changes" />
  </ContextPickerGroup>
</ContextPicker>
```

ただし最初からここまで細分化する必要はなく、

```text
ContextPicker.tsx
ContextPickerTrigger.tsx
```

の2つから始めれば十分です。

特に今回なら、**今ある `#` 用メニューを `ContextPicker` に昇格させて、＋を `ContextPickerTrigger` に変更する**のが一番小さなリファクタリングで済みます。
