# Phase 16-1 の設計判断と検証結果

## パッケージの境界

- UI・Storybook は `apps/nerita-ui`、共通契約は `packages/shared` に置いた。
- Extension Manifest と Host はルートに残し、VSIX の配布パスを維持した。
- `@nerita/shared/*` は型検査と `nerita-source` 条件でソースを公開する。Node.js の実行時には、共有パッケージが生成した CommonJS を使う。
- esbuild と Storybook はソース参照を使い、共有コードの変更を直接監視する。Node.js で動くテストの実行入口は、先に `build:shared` を実行する。
- UI の直接依存は UI 側に宣言した。ルートには Host の依存と、テストから直接使う Lexical・検証ツールを残した。
- `attachmentDrop.ts` の URL 検証は挙動を保った。両環境の標準 URL API に必要な型だけを宣言し、共有パッケージへ DOM 全体の型を導入していない。

## テーマと配布

- 色の対応と明暗の既定色は `apps/nerita-ui/src/ui/theme.css` に集約した。
- VS Code が `body` に設定する変数も優先し、実行中の変更に追従する。TSX からの VS Code 色変数の直接参照はなくした。
- ライト表示で白く埋もれていたメッセージ操作アイコンは、テーマの文字色を使うようにした。
- UI の再ビルド成功後に、JavaScript・CSS を `dist/webview/` へ集約する。
- VSIX を展開して必須成果物とソース非同梱を確認した。展開した配布物でも、VS Code 内の結合テスト10件が成功した。
- Workflow のテスト用 TOML は、配布物へ含めず検証コード側から渡すようにした。

## 検証

- Lint・型検査、ツール用の型検査、textlint、UI 単独ビルド、開発ビルド、本番ビルド、VSIX 生成を確認した。
- Storybook は85件、配布関連は19件、VS Code 内の結合テストは10件が成功した。
- Host の単体・契約・結合テストは初回実行で685件中684件が成功した。残る期待値の不一致は、文言確定後に対象ファイルの11件を再実行して解消を確認した。
- UI レビュー全体を実行し、修正後にチャット・入力設定・Guardrails・テーマ未定義時の対象を再実行した。テーマ未定義時はチャット・Guardrails・Workflow の明暗6件が成功した。
- 画像を開き、変更前後のチャットと、テーマ未定義時の文字・背景・境界・操作アイコンを確認した。
- 一時的な CSS 変更、新しいクラスを持つソースの追加、共有コードの変更で、監視ビルドと配布先への反映を確認した。一時変更は復元済み。
