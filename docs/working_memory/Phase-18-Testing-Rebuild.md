## 検出能力と製品修正

- `test:regressions` は通常版の成功後に、セットアップの完了待ち省略、設定変更後の許可温存、ハンドオフ失敗時の原文送信、接続世代更新の欠落、移動後の履歴除外を個別に注入する。計画完了の欠落、MCP 表示情報の欠落、Fork による元履歴更新、重複要求の再実行、通常結果の JSON 切断も対象にする。アサーション失敗で検出し、準備失敗を検出実績へ数えない。
- 補完候補を常時表示する変更を一時的に入れ、既存 `ComposerMenu` の `/plan` 漏出のアサーションで失敗することを確認した。製品ソースを復元した後は同じ担当が成功した。
- 通常結果の JSON 切断を検出し、`PiFeatureSafety.ts` の結果全体の切断を撤去した。秘密除去と、表示・コード実行それぞれの出力上限は維持する。
- MCP の表示元・省略情報の欠落を検出し、`PiResultDisplay.ts` で許可された2項目を保存・復元へ引き継ぐよう修正した。
- `PiWebTrust.ts` の特定バージョン以外を拒否する判定は、ユーザーが誤りと判断した制限として撤去した。現行拡張の実取得先と信頼境界を検証対象にした。

## 運用上の制約

- SDK の祖先探索を止めるため、一時領域を Git ルートにする。ホーム・Pi・Codex の設定先を隔離し、前回の生成物を使わない。
- Web 受入には導入済み拡張、Git、公開 GitHub への接続が必要。隔離ホームでは認証情報を使わず、検証プロセスの PATH から `gh` のあるディレクトリを外す。取得セッション終了時に clone 先が回収されるため、編集確認までセッションを保持する。
- 実 Webview は通常の開発 Host と一時的な補助拡張を使う。拡張テストモードでは確認ダイアログが禁止されるため、専用プロファイルで `window.dialogStyle` を `custom` にする。Codex 起動前に隔離した `CODEX_HOME` を作る。
- OS 担当だけは既存の準備済み elevated Sandbox と `CODEX_HOME` を使う。試験で書き込む対象は新規の一時領域に限定する。
