# Pi サブエージェントの Host アダプター

## 利用方法

Pi の新規会話・再接続時にエージェント定義を読み、定義があれば組込みの `subagent` Tool を公開する。対象は **pi-subagents 0.71.0**。導入済みパッケージの `agents/**/*.md` をデータとして読み、JavaScript の `index.js` は Host アダプターへ置き換える。インストール先とユーザー設定は変更しない。

単一子の入力例は次のとおり。

```json
{
	"agent": "reviewer",
	"task": "変更したファイルを確認してください",
	"agentScope": "user"
}
```

`cwd` は省略時に親の作業場所を使用する。指定しても親の workspace 外へ移動できない。独立 CLI へ切り替えない。

Stop・切断・ガードレール変更は実行中の子にも伝える。

## AgentViewer

Pi の子も既存の Agent カードに表示し、選択すると子の本文・Tool 履歴を閲覧できる。現在の接続に属する子だけを取得し、親の本文とは分けて保持する。閲覧中は既存の2秒間隔の取得で更新する。

子の閲覧中も、画面下部から親と子の承認一覧へ回答できる。「すべて停止」は親と実行中の子を停止する。同名の子の承認もタスクを常時表示して区別する。

子の会話は親の会話ごとに最大128件まで保持する。各会話は直近256メッセージ・128ツールを表示し、大きな本文とツールの入出力を表示用に短縮する。

### 保存と履歴復元

子の表示用履歴は、親と同じ JSONL 内の `nerita.subagent.v1` レコードに保存する。ワークスペース保存の場合は `.sessions/`、グローバル保存の場合は既存の Pi 履歴保存先を使う。子ごとの独立した JSONL は作らず、履歴一覧には親だけを表示する。

子の起動・状態変更、本文の確定、ツールの開始・終了時に変更した項目を保存する。文字ごとのストリーミングは保存せず、モデル内部の履歴ではなく AgentViewer 用の本文・ツール・状態を対象とする。これらのレコードを親モデルの入力文脈には追加しない。

親の履歴を開くと子カードと会話も復元する。フォークした会話では新しい親 ID に結び直す。子の作業場所は親からの相対パスで記録し、ワークスペース移動後も作業場所の関係を保つ。復元した子は閲覧専用であり、モデル呼出し・承認・ツール実行は再開しない。実行途中で終了した子やツールは停止状態で表示する。

破損した子の記録や保存失敗はエラーとして報告する。この対応より前に終了した子は記録がないため復元できない。旧形式の親履歴そのものは引き続き開ける。

## 定義の探索と優先順位

1. 設定済みで導入済みの `pi-subagents` パッケージの `agents/**/*.md`。
2. Pi agent directory の `agents/**/*.md`。
3. 信頼済み workspace の、起動時 cwd にある `.pi/agents/**/*.md`。

同名定義は後の出所を優先する。`agentScope: user` はパッケージとユーザー定義、`project` はパッケージとプロジェクト定義、`both` はすべてを対象にする。新パッケージに合わせ、既定は `both`。親ディレクトリへの探索は行わない。新たなパッケージをダウンロードしない。定義ディレクトリやファイルがリンクで指定範囲外へ出る場合は拒否する。再帰探索は128ディレクトリ・128ファイルを上限とし、`.chain.md` はエージェント定義から除外する。循環リンクは再訪しない。

`name / description / aliases / tools / model / thinking / systemPromptMode` と Markdown 本文を読み込む。`aliases` はカンマ区切りと配列に対応し、`systemPromptMode` の `append / replace` を子へ反映する。定義はセッション起動時、タスクとモデルは子の起動承認前に固定する。変更した定義を使うには再接続する。

パッケージが未導入でもエラーにせず、ユーザー・プロジェクト定義もなければ委譲ツールを登録しない。

## ガードと承認

- 子の起動を一度承認した後も、子の各操作を共通ガードへ通す。書込みや Shell はそれぞれ承認する。
- 子の承認表示にエージェント名とタスクを付ける。承認先は親の関数から差し替えない。
- `tools` を公開ツールの上限にする。書込みツールがなければ書込み権限をなくし、Shell ツールがなければ Shell 権限をなくす。
- 子の権限は親との共通部分だけにする。親のガードレール設定を継承し、cwd の変更で別の設定へ切り替えない。
- 親の Stop・切断・設定変更を起動待ちと実行中の子へ伝える。完了・失敗時は子を閉じ、親の追跡対象から外す。
- 子に外部拡張と再委譲用 Tool を渡さない。子 SDK 自体はメモリー内で動作し、表示用履歴は親の JSONL に保存する。

## 初期版の制約

これは Nerita のガード付きアダプターであり、元パッケージ全体の互換実装ではない。直接の `agent / task / model / cwd / agentScope` と、`context: fresh / fork`・`async: true / false` を受け付ける。並列・チェーン実行用の `workflowScript` は今後の対応とする。

背景実行と親コンテキストの複製は [ジョブ管理の記録](Pi-Jobs.md) を参照する。`workflowScript` は後続の対応とし、外部 runner は非対応。`runner` を持つ定義は普通の子として実行せず、起動承認より前に拒否する。`oracle` の `defaultContext` など、元パッケージ固有の既定動作は引き継がず、既定では新しい文脈で開始する。明示的な `fork` は親と同じモデルで会話を複製する。`subagents_enable`、管理アクション、追加探索ルート、他パッケージのエージェント宣言、外部拡張・スキルの個別継承設定も対象外。これらが必要な機能は別途対応する。

公開可能なツールは `read / ls / write / edit / powershell / pwsh / bash` とする。実行環境にないツールは公開しない。`grep / find`、外部拡張のツール、孫へのモデル主導の再委譲は未対応。

Windows で定義が `bash` のみを指定している場合、PowerShell に自動置換しない。Shell が必要ならユーザー定義に `powershell` または利用可能な `pwsh` を明示する。`tools` 未指定の場合は親の制限内で利用可能な組込みツールを使う。

`model` 未指定時は呼出時の親モデルを使用する。指定する場合は `provider/model`、または親と同じ provider のモデル ID を使う。利用できないモデルを別のモデルへ自動変更しない。推論指定は `thinking` またはモデル末尾の推論レベルを使用する。

子の最終本文は最大32768文字で親へ返す。独立 CLI の描画・設定コマンド・使用量集計との完全互換は対象外。
