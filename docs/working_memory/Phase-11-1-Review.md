# Phase 11-1 の照合と結合検証

追記：`pi-subagents` の定義を使う [Host アダプター](Pi-Subagent-Adapter.md) を追加した。子へのガード適用と AgentViewer・履歴保存に対応する。

## 状態

2026-09-25 に実装と仕様を照合した。Jev なしで使う共通ガードについて、実 SDK と Extension Host で承認・拒否・取消し・子への制限継承を検証した。Jev の実接続と、外部拡張が独立して起動する子プロセスへのガード適用は未完了として区別する。

## 完了条件との対応

| 条件                               | 実装・検証                                                                    | 状態                               |
| ---------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------- |
| 既知の危険コマンドを検出           | `GuardrailCommands`。削除・変更破棄を検出し、Shell の毎回承認を維持する       | 初期範囲を確認                     |
| 保護パスと workspace 境界          | `GuardrailPaths` と `WorkspacePathPolicy`。正規化、実体、書込み範囲を検査する | 確認                               |
| 任意の Jev 接続                    | `JevGuard` と `JevClient`。既定は外部通信なし                                 | 接続準備済み、実接続待ち           |
| Jev だけで高リスク操作を許可しない | `allow` でも毎回承認。障害時は確認へ戻す                                      | モックで確認                       |
| 承認画面に判定材料を表示           | コマンド・作業場所・実効範囲・判定理由・解析不能な範囲を既存の表示へ渡す      | 確認                               |
| 承認した要求を固定                 | `ApprovedToolCall`。深いコピー、凍結、fingerprint、一回限りの許可             | 確認                               |
| 要求・設定変更で再承認             | 引数、環境変数、ポリシー、対象ファイル、設定世代を検査する                    | 確認                               |
| 拒否・Stop・切断で実行しない       | 拒否前の副作用不在、取消し後の書込み不在を実 SDK で確認する                   | 確認                               |
| 子が親の制限を引き継ぐ             | Host 管理の子・孫で権限非拡大と共通ガードを確認する                           | Host 管理経路のみ確認              |
| Sandbox へ承認要求を渡す           | 既存の製品アダプター・Executor の検証を維持する                               | ガードの確認と OS 隔離の限界を区別 |

Shell の解析は既知のパターンとリテラルのパスが対象。スクリプトや変数展開、任意プログラム内部の動作は解析しきれない。OS による外部読取りの隔離や通信遮断を追加したわけではない。既知の制約は [Sandbox の検証記録](Sandbox-Approval.md) を参照する。

## 今回の追加検証

`tests/piGuardrailsSmoke.ts` を Extension Host の結合テストへ追加した。モデル応答はローカルの模擬サーバーから返し、同梱 SDK・製品 Runtime・ファイル Tool・共通ガードは実装を使用する。ユーザーのモデル認証や課金 API は使用しない。

- 子による `.env` 読取りは人の承認を出す前に拒否し、内容を応答へ含めない。
- 子の通常書込みは承認後に指定内容を保存する。
- 子に書込み・Shell・通信の禁止を設定すると、孫から許可を要求しても拡大しない。
- 人の拒否、親の Stop、ガードレールの再適用、親の切断で対象ファイルを作成しない。
- 閉じた子と切断後の親から、新たな子を起動できない。

既存の `tests/pi-subagent-smoke.mjs` に残っていた「workspace 外 read を許可する」という旧期待値を、現行のガードレールによる拒否へ更新した。このテストは Host 管理の子を対象とし、同名の外部パッケージは使用しない。

`tests/pi-platform-smoke.mjs` の承認表示検査も、旧文字列形式から構造化された実行範囲フィールドへ更新した。Windows 上の OS 模擬であり、macOS / Linux 実機での確認とは区別する。

## 残作業

- **Jev が準備でき次第**、認証管理、明示的な有効化、送信要約と同意、実サービスでの検証を進める。[Jev の記録](Jev-Guard.md) を参照する。
- 単一子の実行と AgentViewer への接続を追加済み。子の表示用履歴は親の JSONL に保存し、履歴の再読込とフォークに対応した。孫への再委譲は残作業として扱う。
- 永続許可や Shell の自動許可は未導入。今回の結合検証を理由に許可範囲を広げない。
