# Phase 11-2 実装・検証記録

2026-09-26。[実装計画](Phase-11-2-Plan.md) に基づき、Pi の Trust Gate と root 単位の信頼管理を追加した。以下の実装範囲と制限を区別する。仕様全体の完了を意味しない。

## 実装した範囲

- `WorkspaceTrustStore` が状態・出所区分・実体の識別情報を保持する。未登録、破損、パス解決失敗、保存失敗は未信頼として扱う。
- Host の `globalState` に保存する。保存途中のマーカーが残った場合は、再起動後も以前の信頼を復元しない。
- `Nerita: Workspace Trustを管理` と取消しコマンドを追加した。ステータスバーからも操作できる。確認ダイアログに実体パスと出所を表示し、確認中の差替えを検査する。
- VS Code の Trust と Nerita の root 単位の Trust を両方要求する。既存の信頼状態は一括移行しない。
- `ApprovalGuard` の前段で Trust を評価する。未信頼の変更・実行要求を Jev や人の承認へ送らない。信頼済みでも既存の Approval と Sandbox を維持する。
- 取消しで待機中の承認と未使用の実行許可を失効させ、接続中の Pi と子を終了する。既存の実行中止経路も使用する。
- Pi は未信頼でも読取り用の接続を作成する。Shell の起動確認を省略し、workspace 内の履歴再開を拒否する。新規履歴は global に保存する。
- Host の read / ls に加え、文字列検索の grep と glob 検索の find を追加した。検索プログラムを起動せず、リンクと大きなファイルを避けて検索量を制限する。既存の Guardrails は維持する。
- multi-root は会話開始時に作業 root を選択する。書込み対象は個別に判定する。複数 root を許可した実行基盤へコマンドを渡す場合は、許可対象の全 root の Trust を要求する。
- 明示した実行対象、cwd の変更、内側の未登録 Git root、junction、再作成された一時リポジトリを検査する。動的なパス、文字列からの追加実行、直接の `git clone` は拒否する。
- workspace-local の Pi 拡張は所属 root の信頼も必要とする。未信頼の候補はロードしない。子と孫は親の信頼コンテキストを共有する。
- 初回登録、信頼・取消し、外部取得先、拒否、子の root、拡張ロード拒否をログへ記録する。root はハッシュで識別し、認証情報やコマンド出力を保存しない。

## Web 取得

導入済み `pi-web-access` 0.30.0 の設定探索順と clone 先の規則を照合した。取得完了通知に依存せず、拡張のロード前にキャッシュの親を未信頼として登録する。設定とパスの変更は実行前にも検査する。未検証のバージョンは接続時に拒否する。

キャッシュ全体は Trust できない。取得したリポジトリを個別に選択して信頼する。同じ場所へ再取得されても、実体が変われば以前の信頼を流用しない。

未信頼の会話では、対応アダプターが検証した HTTPS の `raw` 取得だけを許可する。この経路でも人の承認は必要。認証・proxy・任意オプションや `readable` モードはこの例外に含めない。

実パッケージで公開リポジトリを clone し、取得先が未信頼でコマンドを拒否することを確認した。検証では個人の Git 設定・認証ヘルパー・gh を使用していない。HTTP と clone の検証結果は `dist/pi-web-access-smoke/results.json` にある。

## 残る制限

- Windows の UNC は既存のパス方針に従って拒否する。
- Codex バックエンドは接続時の Trust を要求する。未信頼の root が混在する構成を拒否する。内部の各 Tool Call を今回の共通ゲートで覆う対応は含まない。
- `pi-web-access` 以外の任意の取得・展開・コピーを、出所付きで自動追跡する機構は未実装。出所は workspace / external / external-cache の区分までで、URL やコピー履歴の追跡は残る。
- コマンドの対象検査は明示パスと既知の動的実行形式が対象。信頼済みスクリプトや別プログラム内部の参照先を網羅するものではない。Host で動く任意の信頼済み拡張の直接 I/O も隔離しない。
- 外部取得先の読取りにも既存の Guardrails が適用される。Trust だけで読取り範囲や Sandbox の書込み範囲を広げない。
- OS による通信隔離などの既知制約は [Sandbox 検証記録](Sandbox-Approval.md) のとおり。Trust を追加したことを、これらの隔離の達成と読み替えない。
- UI はネイティブのコマンド・確認ダイアログ・ステータスバーを使用する。Chat header 専用 badge と Trust 用 Webview プロトコルは追加していない。
