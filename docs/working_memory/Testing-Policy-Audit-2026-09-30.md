# テストポリシーの監査結果

基準は `.agents/docs/Testing-Policy.md`。テスト件数の削減率やカバレッジを評価基準にしない。削除・修正の判断は、検出する不具合、保証の所有者、期待値の独立性で行った。

## 削除・修正の判断

| 問題 | 対応と残した保証 |
| --- | --- |
| モデル名だけを変えた同じ拒否分岐 | `piModelCatalog.test.ts` の重複したパラメーターケースを削除。非公開・SDK 側のみ・公開一覧側のみのモデルを拒否し、モデル変更を実行しない検証に集約した。 |
| 本体の変換関数で期待値も作る | `lexicalComposer.test.ts` は `contentKey` 同士の比較をやめ、入力した本文・参照・ブロックを復元結果と直接比較する。内部で生成する ID は固定しない。 |
| 実行が終わってから取消しを検証する | `piApprovedTools.test.ts` は実行中のツールを待機させ、取消しでその実行が失敗することを確認する。Host・SDK・SDK の `signal` なしの各経路を残した。 |
| 停止以外の失敗でも停止テストが通る | 配布物と配布済みランタイムの停止検証は、エラー有無に加えて取消しによる中断を確認する。タイムアウトや初期化失敗を停止成功として扱わない。 |
| 容量制限とは別の拒否でも通る入力 | `codexInputs.test.ts` の容量超過入力を通常の文字で構成した。バイナリ拒否、画像非対応、容量超過をそれぞれの理由で確認する。 |
| 親の入力を検査するだけの子の権限テスト | `workspaceTrust.test.ts` は準備済みの子のコンテキストで評価する。外部ルートの未信頼、明示的な信頼、親の信頼取消しを確認する。 |
| 件数・参照同一性・ハッシュ形式だけの検証 | 検索位置、モデル候補、複製内容、変更後の入力からの独立性、実効設定と拒否結果へ置き換えた。二重起動を防ぐテストは `Promise` の同一性ではなく起動回数と完了を確認する。 |
| 保存したつもりで再起動を確認しない | Agent 設定・既定値・ハンドオフ設定を保存し、別の Store から再読込みして内容を確認する。 |
| 内部の凍結方式を固定する | 承認済み入力や補足判定の改変が、実行に渡す内容へ影響しないことを検証する。`Object.isFrozen` やハッシュの桁数は要求しない。 |
| クラス名・アイコン名・装飾の数値を固定する | UI シナリオは操作、送信値、選択状態、表示、再認証の案内、下書き保持を確認する。フォールバック配色は明暗とコントラスト、拡大は実寸の増減を確認する。 |

## 残したテストの責務

- 通信契約は正常入力と不正入力の受理・拒否を検証する。通信型の生成物と配布スキーマの一致は、配布物の契約として残す。
- 承認・信頼・リンク・秘密情報の境界は、禁止ケースだけでなく許可された操作や初期化の成功と組み合わせる。呼出し回数は二重実行、未承認実行、取消し後の実行を防ぐ用途で残す。
- Host の状態管理、実 SDK との接続、配布後の資産解決、VS Code の登録は別の境界である。同じ機能名だけを理由に削除しない。
- ユーザーの編集内容、改行、コメント、未対応データの保持は利用者のデータを守る仕様である。文字列比較を残す。
- UI の外部から注入したテーマ値への追従、表示中の進捗、無効状態、動きを減らす設定は操作・表示の契約として残す。画像による観察と操作のアサーションは役割を分ける。

## 不具合を検出する確認

製品コードを一時的に変更し、対象テストが失敗することを確認した。検証後は元のバイト列へ復元した。

- 親会話の深いコピーを外すと、`piForkContext.test.ts` が親本文とツール引数の変更を検出して失敗する。
- 添付の容量制限を外すと、`codexInputs.test.ts` が容量超過を受理したことで失敗する。以前のゼロ埋め入力では別の拒否条件で通る余地があった。

全 Host テスト、配布物テスト、補助ツールのテスト、ローカル結合テスト、Lint・型チェックを実行した。
変更した UI シナリオと実 VS Code の結合テスト、日本語コメントの校正コマンドも実行した。
認証済みの外部サービス、実機サンドボックス、利用者環境へのインストールを伴う受入れテストは、この検証の成功に含めない。

UI 成果物は以下の場所に保存した。

- `dist/ui-review-policy/test-results/`
- `dist/ui-review-policy-extra/test-results/`
- `dist/ui-review-policy-final/test-results/`
- `dist/ui-review-policy-corrected/test-results/`

最初の実行では退避コピーと trace 出力が重なり、ファイルロックで失敗した。
別の出力先で再実行して成功を確認した。
追加シナリオの失敗は、表示用ストーリーへの誤った有効化要求とセレクターの重複だった。
エラー時の再認証案内と、対象カードの本文で確認するよう修正した。
フォールバックの明るい画面とスライダー拡大後の画像を開いて確認した。
UI 実装自体の変更は行っていない。
