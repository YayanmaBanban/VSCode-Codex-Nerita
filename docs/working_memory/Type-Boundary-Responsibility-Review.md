# 型境界・責務の変更時に維持する条件

型境界・責務のレビューで指摘した R1〜R8 は対応済み。この文書には、今後の変更でも維持する設計上の条件を記す。

## Codex の状態と非同期処理

### 状態の管理と初期化

- 会話状態と接続を機能別オブジェクトに複製しない。通知は「履歴の競合処理 → 設定 → 子 → 親ターン → 一覧」の順で配信する。
- 新規会話では設定を初期化し、接続世代が変わっていないことを確認してから一覧を初期化する。送信は初期化の完了後に受け付ける。履歴復元では一覧のアーカイブフィルターを維持する。
- 子の管理と承認処理に渡す状態取得関数は、内部の状態を複製せず、同じオブジェクトへの参照を返す。通知と取得結果の競合判定に、参照の同一性を使うためである。

### 履歴復元と送信・停止

- 履歴復元と送信準備では、接続世代、会話、操作オブジェクトが処理開始時と同じか照合する。古い処理の後片付けで、新しい操作の待機状態を解除しない。全文出力への参照は復元が確定したときだけ引き継ぎ、競合・取り消し時には破棄する。
- ターンの生成・更新・解除は `CodexRun.ts` に集約する。開始応答前の通知は、ターン確定後に到着順で適用する。停止要求は一度だけ送り、停止応答後も完了通知までは停止待ちの状態を維持する。
- 停止操作では送信準備を取り消してからターンを停止する。明示的な停止・失敗後に、待機中の追加指示で実行を再開しない。受け付けられたか不明な追加指示は自動再送しない。

### 接続と終了処理

- 前の接続の終了処理を待ってから次の接続を開始する。旧世代の通知は会話 ID が一致しても適用しない。ログイン通知後は、同じ接続の認証状態を読み直す。
- 終了時は接続の終了処理を開始した直後に、UI の購読と全文出力を解除する。変更時は、接続の取り消し・世代照合・履歴復元・送信・停止を検証する既存テストで確認する。

## 外部データと表示用の型

- Codex 項目の受け取り時に検証する `id`・`type` と、項目種別ごとの未検証データを区別する。具体的な型を追加する場合は、解析処理と利用側を同時に変更してから、後段の検査を減らす。
- 共有するツール本文の型には判別共用体を使う。全文を出力ストアへ退避した後は、配信する状態の `commandOutput` からも削除する。保存用の全文と配信用のプレビューを分ける。
- 汎用の伏字変換では、変換後も元の型を満たすとは限らない。SDK の結果・保存メッセージ・認証通知ごとのデータ形式を維持し、判別子や制御フィールドが増えたら、それぞれの専用変換を更新する。
- 認証 URL、画像データ、MIME タイプが伏字の対象になる場合は、破損した値を返さず、非公開にしたことを示す本文や情報通知へ置き換える。
