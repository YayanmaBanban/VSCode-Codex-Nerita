# Pi のジョブ管理と背景実行

## 実装範囲

共通ジョブ管理、バックグラウンド実行、親コンテキストの複製を追加した。TOML、WorkflowScript、React Flow は後続の計画で扱う。外部 runner は Nerita では非対応とし、指定時に拒否する。

`subagent` の入力例は次のとおり。

```json
{
	"agent": "worker",
	"task": "変更箇所を確認してください",
	"async": true,
	"context": "fork"
}
```

既定は `async: false` と `context: fresh`。背景実行は `jobId` をすぐ返す。親モデルは `subagent_job` の `list`、`read`、`cancel` で状態・結果を取得し、個別取消しも行える。`read` と `cancel` は `jobId` が必須。同じ親会話のジョブだけを対象とする。

## 寿命と承認

ジョブは起動待ち、実行中、承認待ち、完了、失敗、取消し、中断を区別する。同時実行は最大4件で、承認待ちも枠を使用する。1会話あたりの保存上限は128件。親の応答終了後も背景ジョブは継続し、承認は既存の承認画面へ表示する。

AgentViewer のカードとジョブは同じ ID を使用する。親が完了していても、子の閲覧中は承認と「すべて停止」を操作できる。通常の Stop は起動待ちも含めて全ジョブを取り消す。個別取消しは他のジョブへ影響しない。

接続終了、VS Code 終了、親の設定による接続の作り直しでは子も終了する。ガードレールの変更は、受付時の設定世代に結び付いたジョブを取り消す。背景実行でも起動承認と操作承認を省略しない。子の権限は親の上限を超えない。

## 会話の複製

`fork` は起動要求時点の親会話を固定する。親と同じモデル・プロバイダーだけを認め、別モデルへの自動切替は行わない。ユーザー本文、アシスタント本文、完了したツール交換を複製し、未完了のツール呼出しと独自の実行記録は除く。

複製する会話は最大1024メッセージ、JSON 表現で4194304文字。超過時は黙って切り捨てず拒否する。承認待ちや実行待ちの間に親へ追加されたメッセージは子へ追加しない。親のシステムプロンプトや外部拡張は複製せず、子の定義を適用する。

会話にすでに含まれる情報は子へ渡る。ファイルの読取り制限とは別の共有範囲として扱う。子の内部会話はメモリー内に保持し、複製内容を独立した履歴ファイルへ保存しない。

## 保存と復元

ジョブ状態と結果は親の JSONL の `nerita.job.v1` に保存する。結果は表示用の文字列として最大32768文字まで保持する。子の本文・ツールは既存の `nerita.subagent.v1` を使用する。保存先は既存のグローバル設定またはワークスペースの `.sessions/` に従う。

再接続時は選択ブランチの履歴だけを復元する。起動待ち・実行中・承認待ちの記録は中断として扱い、自動実行・自動承認は行わない。会話のフォークでは親 ID を新しい会話へ付け替える。復元後のジョブは閲覧専用で、途中からの再開は対象外。
