# Jev 補足判定の接続準備

## 状態

**Jev が準備でき次第、認証設定と実サービスでの検証する。**

現在はアカウントがないため、仕組みとモックによる検証までを実装した。既定では未接続で、外部への通信は発生しない。API キーの取得・保存・設定画面は未実装。実サービスの応答や判定品質は未確認。

## 接続点

- `src/extension/security/JevGuard.ts`：任意の判定器、接続世代、時間切れと取消し、送信する要約。
- `src/extension/security/JevClient.ts`：公式の tool-guard REST API アダプター。キーを閉包に保持し、固定した HTTPS 接続先だけを使用する。
- `src/extension/security/ApprovalGuard.ts`：決定論的な検査の後、人による承認の前に補足判定を挟む。
- `tests/unit/jevGuard.test.ts`：接続なし、各判定、障害、取消し、送信内容、HTTP 契約の検証。

将来、Host の認証処理から `jevGuard.configure(createJevReviewer(apiKey))` を呼ぶ。解除は `jevGuard.configure()` とする。接続変更は古い世代の判定待ち・承認・実行許可を取り消す。workspace の JSON やエージェント入力から接続を有効化する経路は設けていない。

## 判定の扱い

決定論的な拒否では Jev を呼ばない。workspace 内の通常の read など、承認不要の操作も対象外。承認対象の Tool Call だけを判定し、`deny` は許可を発行しない。`allow / confirm / review` は既存の毎回承認を維持する。判定と理由を承認画面に表示し、承認対象の fingerprint にも含める。

通信失敗・不正応答・8 秒の時間切れでは `confirm` として人の確認へ戻す。Stop やガードレール変更による取消しでは承認を出さない。生のエラー本文は表示しない。応答サイズは 32KiB に制限する。Jev は実行先ではなく、Sandbox の制限を変更しない。

エディターの「検査」は従来どおりローカルの決定論的な検査のみ。ボタン操作で外部へ情報を送らない。

## 送信範囲と制約

現段階では Tool の分類、引数の個数、コマンドの有無、固定した制約だけを送る。生のコマンド、ファイル内容、パス、環境変数、任意の拡張 Tool 名、会話は送らない。ユーザー意図や実際の操作内容を渡していないため、意味的な危険度判定の品質は評価できない。この構造要約は接続準備用であり、十分な意味解析ができる状態とは扱わない。

## Jev が準備でき次第

1. 公式 API の契約・利用条件・応答形式を再確認する。
2. VS Code SecretStorage へのキー保存と削除、利用者による明示的な有効化を実装する。認証情報を workspace ファイルに置かない。
3. 外部へ送る情報を利用者に提示する。秘密値を除去した操作要約とユーザー意図の扱いを決め、送信への同意を得る。
4. 必要な文脈を含む要約を整備し、無害な専用 fixture で実サービスの判定を検証する。
5. 認証失敗、利用制限、障害、遅延、Stop、切断、子 Runtime からの呼出しを実接続で確認する。
6. 実際の承認画面と Sandbox への受け渡しを確認し、検証結果をこの記録へ追記する。

参考： [Jev 公式 API ドキュメント](https://www.jevai.org/docs)。実装時点では `/api/v1/decisions/tool-guard` と `code / data.decision / data.guidance` の契約を使用した。
