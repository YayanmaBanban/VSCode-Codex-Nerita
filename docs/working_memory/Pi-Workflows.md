# Pi の TOML ワークフロー

## 実装範囲

`.pi/workflows/*.toml` を正規の定義として、検証、WorkflowScript 生成、Pi の Worker による実行、子会話の継続と Fork に対応した。React Flow エディタの初期版も実装した。任意の JavaScript、条件式、retry、外部 runner、再起動をまたぐ実行再開は対象外。

生成スクリプトはメモリー内で保持する。子の起動は Pi の `launch` 接続口から Nerita のジョブ管理へ戻す。パッケージの標準拡張 entry や独立 CLI は起動しない。

## 利用方法

ユーザー側の Pi パッケージ設定に登録した `pi-subagents 0.71.0` を使用する。プロジェクト側だけに登録されたパッケージを実行エンジンとして採用しない。未導入時は自動取得せず、ワークフロー用ツールを公開しない。別バージョンでは実行時に拒否する。

`tests/fixtures/workflows/implementation-review.toml` に、実装、会話を複製したレビュー、独立したテスト観点の確認、元の子による修正の例を置いた。利用するワークスペースの `.pi/workflows/` に配置し、タスクを編集する。

親モデルから使用するツールは `subagent_workflow`。ファイル名は `.pi/workflows/` 直下の TOML を指定する。

```json
{ "action": "validate", "file": "implementation-review.toml" }
```

検査では TOML と Agent・モデルの整合性を確認し、生成したスクリプトを返す。子の起動承認と子の実行は行わない。定義ファイル自身の読取りには既存のガードを適用する。

```json
{ "action": "run", "file": "implementation-review.toml", "async": true }
```

`async` の既定値は false。背景実行では親ワークフローの `jobId` を返す。既存の `subagent_job` で結果取得と取消しを行える。各ステップにもジョブと AgentViewer 用の会話を作り、既存の承認画面を使用する。

## TOML の仕様

| 項目                     | 意味                                                       |
| ------------------------ | ---------------------------------------------------------- |
| `version`                | 現在は1だけを受け付ける                                    |
| `name`                   | ワークフロー名                                             |
| `outputs`                | 最終結果として返すステップ ID の配列。必須                 |
| `limits.max_concurrency` | 1〜4。既定3。Nerita 全体の上限も適用する                   |
| `limits.timeout_ms`      | 1000〜3600000。既定600000                                  |
| `steps[].id`             | 重複しない英字始まりの ID。最大64文字                      |
| `steps[].agent`          | Agent 定義名または別名。resume では指定しない              |
| `steps[].task`           | 子へ渡す本文。最大32768文字                                |
| `steps[].depends_on`     | 先に完了する必要があるステップ ID                          |
| `steps[].group`          | 表示分類。初期エディタでは値の編集のみ。実行順に影響しない |
| `steps[].resume`         | 先行ステップの子会話を継続する                             |
| `steps[].fork`           | 先行ステップ完了時の会話を複製する                         |

定義ファイルは最大262144バイト、ステップ数は最大32。未知の項目、重複 ID、循環、存在しない依存先、出力先を拒否する。本文では `{{ step.output }}` だけを結果参照として扱う。参照先は直接または推移的な依存先に含める。引用符・改行・JavaScript の構文を含む本文もデータとして生成し、評価しない。

記述順を依存順へ正規化し、必要な依存先だけが完了した時点で子を起動する。並列の無関係な遅い枝を待つ段階区切りは作らない。失敗したステップの後続は起動しない。独立した枝は終了まで進め、最終的にはワークフロー全体を失敗として返す。

## 子会話の継続と複製

`resume` は元の SDK セッション、Agent、モデル、権限を使う。新しいステップの起動承認を要求し、その後の操作承認を現在のジョブ・タスクへ結び付け直す。同じ完了時点からの二重 resume を拒否する。さらに続ける場合は、直前の resume ステップを次の継続元として指定する。

`fork` は参照先ステップの完了時に固定した会話を使う。元の子が後から resume されても複製内容は変わらない。別の Agent 定義を使用できるが、同一モデル・プロバイダーに限定する。複製元の書込み・Shell 権限を上限にして、新しい Agent のツール指定でさらに制限する。

Fork の生成スクリプトでは、参照先の実行 ID を `neritaFork` として Host へ渡す。これは Nerita の接続口専用の項目で、生成スクリプトを Pi 標準ツールへ直接渡す互換性は保証しない。実行エンジンと静的検査は Pi を使用し、子の継続・複製は Nerita が管理する。

会話のスナップショットには既存の Fork と同じサイズ上限とツール交換の検査を適用する。保持した SDK と内部会話は、ワークフローの終了・失敗・取消し・切断時に回収する。表示用の履歴は親の JSONL に保存し、再読込とフォークでもワークフローとステップの親子関係を保持する。

## Workflow エディタ初期版

コマンド `Nerita: Pi Workflow を作成` で `.pi/workflows/` に定義を作る。既存の TOML はファイルを開くと専用エディタで表示される。テキストエディタで開く場合は VS Code の「エディターを再度開く」を使う。既存ファイルは新規作成コマンドでも上書きしない。

- 上部の保存・検証・実行・停止を固定し、グラフとステップ設定を別ペインで表示する。
- Agent 名、タスク、依存先、出力、Fresh・Resume・Fork、グループを編集する。ワークフロー設定には名前・同時実行数・制限時間を置く。
- 端子を結んで依存を追加し、選択した線を Delete / Backspace で削除する。キーボードだけでも選択欄と依存先のチェック欄から編集できる。
- ID の変更時に依存・結果・会話・出力の参照を更新する。会話や結果が参照されているステップの削除は拒否する。
- TOML とグラフを切り替える。グラフでの編集は TOML を再生成するため、コメントと元の書式を保持しない。ノードの位置は保存しない。
- 「検証」は接続不要で TOML と依存関係を検査し、生成スクリプトを表示できる。Agent・モデル・Pi の静的検査は実行開始時に行う。
- 実行は保存済みの内容だけを受け付ける。同じルートに接続した Pi セッションを使用し、親モデルへの送信を挟まず既存のジョブ管理へ接続する。
- 承認・履歴は既存のチャットと AgentViewer に表示する。エディタの停止はその実行だけを対象とする。初期版ではパネルを閉じると実行を停止する。

文書の版を検査して外部編集との競合を通知する。古い要求で入力を上書きせず、VS Code の改行正規化も受け付ける。実行開始時にはファイルの内容とエディタが確認した保存内容を照合する。ワークスペース外に向くリンク、異なるルートの Pi 会話、未導入のパッケージを実行に使用しない。
