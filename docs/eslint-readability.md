# 独自 ESLint 可読性ルール

ルールは [config/eslint/](../config/eslint/) に置き、ESLint 10 の Flat Config から `nerita/*` として読み込む。

式やコールバックの構造を検査するルールは、行数・改行位置・識別子の長さでは判定せず、パーサーの `visitorKeys` で AST を走査する。`no-multiline-if-condition` は、ユーザー指定の改行制約をトークンの位置で判定する。型情報は判定に必要ない。短絡評価・例外の発生条件・型の絞り込みを保つため、自動修正は提供しない。

## 導入範囲と検証

9つの独自ルールを製品ソース全体へエラーとして適用し、Svelte には用途別に2つのルールを追加する。

| ルール | 適用範囲 |
| --- | --- |
| 条件式・コールバック・変数名を検査する6ルールと、コメントを求める3ルール | `apps/**/src/**/*.{ts,tsx,svelte}` と `packages/shared/src/**/*.ts`。Webview・Extension Host・DLC・共有契約を含む。 |
| `nerita/require-effect-reason` | `apps/nerita-ui/src/` と `apps/nerita-ui/stories/` の `.svelte`・`.svelte.ts`・`.svelte.js`。 |
| `nerita/require-cn-for-long-class` | 製品 Webview の `apps/nerita-ui/src/**/*.svelte`。 |

コメントを求める3ルールは次のとおり。

- `require-member-function-comment`
- `require-file-comment`（[ファイル単位の検査](../config/eslint/require-file-comment.cjs)）
- `require-declaration-comment`（[宣言単位の検査](../config/eslint/require-declaration-comment.cjs)）

製品ソース全体へ適用する範囲では、標準の `no-nested-ternary` を、直接の入れ子も検出する独自ルールで置き換えている。範囲外では標準ルールを維持する。`no-restricted-syntax` の可読性用セレクターも独自ルールへ移行済み。TypeScript の `enum`・`default export`・非同期の `forEach` の禁止と、既存の Storybook 用の例外は維持する。

- `pnpm test:eslint`: 実例に基づく `RuleTester` の正常系・異常系のケースと、各製品領域に適用される設定を検証する。`pnpm check` からも実行する。
- `pnpm lint:readability`: TypeScript の製品ソースを同じ独自ルールで検査し、ルール別の件数と診断位置を表示する。診断や構文解析エラーがあれば終了コードは1になる。`.svelte` コンポーネントを含む通常の検査には `pnpm lint` / `pnpm check` を使う。

`lint:readability` は、生成物・同梱外部ソースを検査から除く既存の ESLint 設定を引き継ぐ。テストや Storybook のファイルは検査対象に含めない。

## 判定の基準

### `nerita/no-skipped-variable-number`

製品ソースの関数内で、`const`・`let`・`var` によって宣言したローカル変数の末尾番号を検査する。分割代入・ループの変数も含む。`value2` には `value` または `value1`、`value3` 以降には直前の番号の変数が必要。欠番の位置ごとに報告し、宣言順は問わない。番号なし・末尾が0または1の変数自体は報告しない。

同じ番号系列の変数として数えるのは、同じ関数内の現在のスコープと親スコープで参照できる変数・引数とする。別関数、モジュール直下、兄弟・子ブロックの変数、型名、関数宣言は数えない。引数・プロパティ名・関数名自体の欠番は検査しない。

名前から番号の用途を推測せず、末尾の数字列を番号として判定する。参照先を誤って変えないよう、自動修正は提供しない。

### `nerita/no-complex-boolean-expression`

`&&` / `||` の式を、直接渡すコールバックの内部も含めて検査する。無関係な関数宣言や、オブジェクトに保存する関数の内部へは入らない。同じ構造の内側の論理式は二重報告しない。

コールバック、複数の `every` / `some`、または入れ子の呼び出しを持つ式だけを採点する。点数は次の要素の合計とする。

| 採点する要素 | 点数 |
| --- | --- |
| `&&` / `||` による論理演算 | 演算の数 |
| インラインコールバック | コールバックの数 × 2 |
| 同じ関数内の最大呼び出し深さ | 1段を超えた分 × 2 |

呼び出し深さは関数をまたいで加算しない。`??` は論理演算の点数に含めない。点数が `maxScore`（既定6）を超える場合に報告する。

単純な比較の列挙、`!(a < b && b < c)`、`a && keys.every(predicate)` は許可する。関数全体の認知的複雑度は SonarJS が検査する。このルールでは、1つの評価式に論理演算・コールバック・呼び出しが重なる構造を検査する。

`if` の条件式と `return` の式では、点数とは別に次の構造を検出する。

- `every` / `some` のインライン述語が `&&` / `||` による複合条件を持つ。
- 同じ関数内の判定で `&&` と `||` が混在し、検証の呼び出しも含む。

単一の比較だけの述語、名前付きの述語、関数呼び出しを含まない単純な比較は引き続き許可する。別関数の内部は外側の判定へ合算しない。複合的な検証を先に評価し、結果を変数へ代入してから `if (!valid)` や `return valid` で使う場合は、この追加条件の対象外とする。

検証を分離するときも、元の短絡評価を保つ。先の判定で拒否すべき場合には、後続の検証をしない。

オブジェクト・配列・JSX 要素・JSX フラグメントを組み立てる `return` 全体は、1つの真偽値式として追加判定しない。独立した表示条件を合算せず、戻り値のデータ構築と真偽値の検証を区別する。

JSX が `&&` の右辺や三項演算子の分岐にある場合も、表示条件を外側の式へ合算しない。JSX 内外は別の評価範囲として扱う。内部の論理式は点数による検査を続け、コールバック内の `if`・`return` にある検証式も独立して検査する。内外の両方が違反する場合は、それぞれの式を報告する。

### `nerita/no-nested-ternary-expression`

三項演算子の分岐側にある、別の三項演算子を検出する。オブジェクト・配列・JSX・呼び出し引数のコールバック内にあるものも含む。1つの入れ子を外側の式で一度報告する。

条件側にある三項演算子は分岐の入れ子として扱わない。分岐で値として返す関数や、オブジェクトに保存する関数は独立した処理として扱う。標準ルールが検出する、直接の三項演算子の入れ子も対象に含む。

### `nerita/no-complex-inline-callback`

`CallExpression` / `NewExpression` の引数に渡す関数を検査する。型注釈、オブジェクト、配列、三項演算子の分岐を挟む場合も対象にする。アクセサーや、別に定義した名前付き関数は対象外。内部の別関数の処理は合算しない。

次のいずれかを満たすと報告する。

- 文の数が `maxStatements`（既定8）を超える。ブロック自体は数えず、変数宣言も1文として扱う。
- `if`・ループ・`switch`・`try` の制御構文の入れ子が `maxControlDepth`（既定2）を超える。
- `await` の数が `maxAwaits`（既定2）を超える。
- `await` が2個以上あり、上記の制御構文も2個以上ある。取得と複数のガードを組み合わせる処理を切り出すための条件であり、上記の上限設定とは別に判定する。

単純な `map(item => item.id)`、短い `save` コールバック、単純な `new` 式は許可する。コールバックの入れ子の段数は、既存の `max-nested-callbacks` が引き続き検査する。

### `nerita/no-await-in-condition`

`if`・`while`・`do while`・`for`・三項演算子の条件内にある `await` を、その位置で報告する。条件内の別関数に属する `await`、`for` の更新式、ループ本体、三項演算子の分岐側は含めない。条件式が重なっても、同じ `await` を二重報告しない。

修正では、`ready && await trusted()` の取得を無条件に前へ移動しない。先に `ready` を判定してから取得する。ループは反復ごとの取得・更新・`continue` の順序を維持する。

### `nerita/no-multiline-if-condition`

ユーザー指定の追加方針として、`if` キーワードから条件式を閉じる `)` までが複数行になる書き方を禁止する。`else if` も対象とし、式本体が1行でも外側の括弧を別行に置けば報告する。条件の中のコメントによる改行も含める。本体や、本体の前にあるコメントの改行は対象外。

このルールは構造の複雑さを測る既存ルールとは別の表示上の制約で、単純な条件でも複数行なら報告する。文字数の上限は追加せず、Prettier の整形後に条件を1行へ収める。自動修正は提供しない。`while` や `return` の改行は、このルールの対象にしない。

修正例を示す。

```ts
const busy = state.workItems.some((item) =>
	["running", "stopping"].includes(item.status),
);
if (!busy) {
	return state;
}
```

判定を分離する際は、元の論理式を1つの変数の初期化式として評価するか、前段のガードを通過してから次の値を評価する。短絡評価と型の絞り込みを維持する。

### `nerita/require-member-function-comment`

クラスのメンバ関数の宣言直前に、役割・理由・制約を説明するコメントを必須にする。アクセス修飾子（`public` / `protected` / `private`）や、`async` / `static` / `generator` の有無を問わない。コンストラクター、getter / setter、抽象メソッド、関数を初期化するクラスフィールドも対象。連続する同名・同種のオーバーロード宣言と実装は、グループ内に共通の説明を1つ認める。説明が欠けている場合も一度だけ報告する。

説明は JSDoc・ブロックコメント・行コメントのいずれでもよい。装飾子がある場合は最初の装飾子の直前に置く。コメントと宣言の間に空行を挟まない。前のメンバの行末コメント、関数本体内のコメント、クラス全体のコメントは説明として数えない。空のコメントと、ESLint / TypeScript の解析指示だけのコメントも対象外とする。

コメントは既存の規約に従って日本語で書き、関数名の言い換えではなく実装の役割・制約を説明する。ルールはコメントの存在と配置を判定し、内容の妥当性や実装との一致はレビューで確認する。オブジェクトのメソッド、通常の関数、関数の型だけを持つ未初期化のフィールドは対象外。定型文を埋める自動修正は提供しない。

### `nerita/require-effect-reason`

`$effect`・`$effect.pre`・`$effect.root` を登録する文の直前に、扱う副作用と `$effect` が必要な理由を説明するコメントを求める。既存の説明コメントも認め、書式や定型の接頭辞は指定しない。`$effect.root` の解除関数を保存する変数宣言や `return` も対象にする。

コメントは行コメント・ブロックコメント・JSDoc のいずれでもよい。文との間に空行を挟まない。前の処理の行末コメント、コールバック本体内のコメント、空コメント、解析指示、ルーン名だけのコメントは説明として数えない。

`$effect.tracking()`・`$effect.pending()` は副作用の登録ではないため対象外とする。同名のローカル関数やインポートも、Svelte のルーンとして扱わない。

このルールは `$effect` 自体や状態への書き込みを禁止しない。値の計算は `$derived` を優先し、`$effect` の必要性とコメントの内容は開発ガイドラインに従ってレビューする。理由の定型文を埋める自動修正は提供しない。

### `nerita/require-cn-for-long-class`

製品 Webview の `apps/nerita-ui/src/**/*.svelte` にエラーとして適用する。`class` に直接書いた文字列部分が120文字を超える場合、`cn()` の複数引数への分割を求める。オプションの `maxLength` で上限を指定できる。

引用符付き・引用符なしの属性、`class={"..."}`、テンプレート文字列を検査する。先頭と末尾の空白を除き、連続する空白や改行は1文字として数える。補間を含む属性やテンプレート文字列では、動的な値を評価せず、直接書かれた文字列部分を空白でつないで判定する。

変数参照・関数呼び出し・条件式・配列・オブジェクトや、`cn()` の引数内部は検査しない。短い属性、`class:` ディレクティブ、他の属性、ストーリーは対象外とする。分割のまとまりと import の選択は利用側で判断するため、自動修正は提供しない。

```svelte
<div class={cn("flex min-w-0 items-center", "gap-2 rounded border", "hover:border-focus")} />
```

## 設定変更の運用

ユーザー承認なしに設定・独自ルール・テストを変更しない。誤検出の疑いは対象コード・ルール・理由を提示し、エラー回避のために条件を緩めない。

実効設定のテストでは、後段の設定による上書きや、`pnpm check` からのルール検証の実行漏れを検知する。`AGENTS.md` とテスト自体も編集可能なため、Host のファイル変更権限を技術的に制限する仕組みにはならない。
