# 技術比較

読者が下したい判断、候補、予算や実行環境などの制約、比較時点を入力にする。候補や制約が結論を変える場合は、確認または条件付きの比較にする。

1. 選定目的から評価軸を決め、候補を同じ用途、バージョン条件、負荷、測定方法で調べる。条件をそろえられないセルはその理由とともに表示する。
2. 構成案では具体的な選定場面、比較軸の優先順位、結論を出す順序を選ぶ。構成承認後に、比較表、主要なトレードオフ、条件別の結論を書く。
3. 各セルや結論の近くに根拠を置く。仕様・計測結果と、読者の条件を踏まえた筆者の評価を区別する。未計測を数値で埋めない。
4. 比較表と見出しだけを読んでも条件を誤認しないか、条件が変わった場合にも選定理由が説明できるか確認する。モバイルで比較軸と候補の対応を保てるか確認する。

比較条件、共通の軸、根拠付きの比較表、トレードオフ、推奨が成立する条件を出力する。
