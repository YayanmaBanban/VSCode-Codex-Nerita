# Final Takeaway Review

初稿と改稿で、最後の節と最後の段落をそれぞれ読む。短い報告やリンクの末尾まで含め、読者が記事の核心と次に取る行動を自分の言葉で答えられるか確かめる。`brief.coreThesis` と承認した題名の `titleContract.promise` に照合し、タイトル契約がない回は承認された題名と章の主張を使う。

制作記録では、困ったこと、実際に工夫したこと、分かった範囲をつなぐ。比較では結論が成立する条件、チュートリアルでは完了結果と次にできることを示す。コマンド・環境条件・JSONL が続く末尾は該当する操作節へ整理し、結びには読者がその知識を使う場面を残す。既に明確な結論と行動がある場合は、その段落を採用できる。

指摘は `fidelityReview.issues[]` の `type: "final-takeaway"` に、最後の段落の位置、見失った主張、修正案、根拠を記録する。改稿後は同じ約束・主張と再照合し、`resolved / unresolved` と根拠を残す。提出されていない結果や効果を足さない。
