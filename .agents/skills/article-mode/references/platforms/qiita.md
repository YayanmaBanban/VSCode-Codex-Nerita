# Qiita アダプター

確認日 2026-11-19。[Qiita Markdown 記法](https://qiita.com/Qiita/items/c686397e4a0f4f11683d)・[画像アップロード仕様](https://help.qiita.com/ja/articles/qiita-image-upload)

1. 元の Markdown から閲覧用コピーを作る。長い修正前後などの補足を `<details><summary>修正前後のコメントとコードを見る</summary>` と `</details>` で囲む。`open` を付けず、開始タグの次と閉じタグの前に空行を置く。タイトルを HTML テキストに適した形へエスケープし、内部のリスト・コードフェンス・リンクを維持する。
2. SVG を描画して PNG に書き出す。ブラウザで書き出す場合は日本語フォントの読み込みを待ち、SVG 全体を欠けずに画像化する。ローカルプレビューには検証用 PNG のパスを使う。本番用の画像 URL は、ユーザーが提供したものか別途承認されたアップロード先の到達を確認してから設定する。画像の横幅は本文で縮小されたときにも読めるよう確認する。Qiita の画像アップロード対応形式に SVG は含まれない。
3. `![関係を説明する代替テキスト](確認済みの画像URL)` と本文キャプションを置く。Qiita 用に編集するのは参照先であり、図の変更は SVG に戻って行う。重要な主張、前提、注意、変更の要約は折り畳みの外側に置く。

Qiita エディタのプレビューまたは [Qiita CLI](https://github.com/increments/qiita-cli) の `npx qiita preview` で確認する。CLI は認証や記事同期を伴うため、必要な利用権限と対象を確認してから隔離ディレクトリで使う。公開ページの公式サンプルを使った構文確認は、対象原稿のプレビューとは区別する。

PC・スマホ幅で閉状態、展開後のリスト・コード、リンク、開閉、コードのコピーを検証する。PNG のラベル、接続、矢印の向きが SVG と一致し、記事幅で読めるか確認する。プレビュー種別と版、画面幅、未確認項目を記録する。

承認構成に `detailPlan` がある場合は [折り畳みの表示照合](../folded-details.md) の ID を使う。出力で `summary` の直後に空行があり、Markdown のリストやフェンスまで展開できるか確認する。
