# 参考元と根拠リンクの置き方

Brief を作るときに、ユーザーが示した資料と調査で見つけた資料を控える。資料ごとに、何の根拠として使うか、制作に影響したことを本人が確認したか、記事のどの箇所に関係するかを確かめる。著者、記事名、公開日が確かめられないときは判明した項目だけを用いる。

| 役割 | 配置と書き方 |
| --- | --- |
| `inspiration` | 制作への影響をユーザーが明示した資料。読者が記事の動機と価値を理解したあと、最初の実例に進むまでの短い文で、分かっている著者・記事名と、どの考え方をどこへ取り入れたかを紹介する。 |
| `claim-evidence` | 仕様、コード、結果など、主張を裏付ける資料。対応する本文の近くに、リンク先で何を確認できるか分かる文やラベルを置く。版や箇所が重要なら指定する。 |
| `further-reading` | 本文の理解を助ける補足資料。役割を短く添えて、記事末尾の参考リンクに置く。 |
| `unclassified` | URLの提供だけで用途が不明な資料。Brief に控え、記事への配置や制作の着想元としての紹介は用途が判明してから決める。 |

参考元が1件なら導入に短い段落を置く形でもよい。制作への影響と技術的根拠の両方を担う資料は、役割ごとにどの箇所に必要かを検討する。自作の説明と引用を読み分けられるよう、引用範囲を示し、利用条件を確認する。根拠までまとめて末尾へ移し、本文だけでは検証しづらくなった場合は `reference-placement`。確認していない制作への影響や、引用と自作の境界が曖昧な場合は `attribution-misattribution` とする。

`brief.references[]` を使う場合は `id`、`url`、`title`、`author`、`role`、`providedBy`（`user` または `agent`）、`confirmedInfluence`、`influencedPart`、`claimIds`（Brief の根拠 ID）、`verificationStatus`（`verified`、`unverified`、`unavailable`）を持つ。著者・題名・影響箇所の未取得値と、影響自体が未確認の場合は `null` にする。1件が複数の役割を担うときは同じ URL を異なる ID で記録できる。

候補と確定構成は任意の `attributionPlan` に `referenceId`、`placement`（`introduction`、`near-claim`、`end`）、`note`（位置・紹介文の要点・導入への影響）を記録する。技術的根拠を置く項目には対応する `evidenceId` を指定する。独立審査では各案の出典の事実を共通にし、紹介の位置と流れ、主張からリンクへの近さを比べる。確定後に制作への影響や技術的主張を変える場合は構成承認へ戻す。
