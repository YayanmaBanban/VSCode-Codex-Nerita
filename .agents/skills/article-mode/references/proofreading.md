# 日本語校正と意味の照合

対象記事と参照実装を入力にする。記事 Markdown の校正に [既存の日本語校正スキル](../../japanese-proofreading/SKILL.md) を使える環境では、Markdown・文章の参照ルールと指定範囲の手順を使い、対象ファイルを明示する。校正依頼と記事のレビュー範囲に限り実行する。スキルや実行環境がなければ記事と根拠を手作業で照合し、静的検査の状況を未実施と記録する。

1. 静的検査の指摘、JSONL の文脈確認候補、記事を読んで見つけた問題を確認する。`ai-slop-pattern` は静的検査を失敗させる高確度の候補、`ai-slop` は単独では失敗させない文脈確認候補として扱う。AI が書いたかどうかの判定や一括置換には使わない。
2. 修正する箇所ごとに、対象、条件・例外、否定、程度・確実性、作用、数量、技術用語を変更前後で照合する。技術的な誤りを正す場合は、表現の校正と区別して根拠を残す。
3. 例に含むキー・識別子・プロトコル値は使用箇所を確認し、周囲の自然文と区別する。文章の校正に合わせて実装の動作を変えない。
4. 同じ範囲を再検査し、静的検査の結果と意味の照合結果を記録する。

記事は見出しの抽出に加えて、本文を順に通読する。[`Coherence`](principles.md) の観点で、導入の疑問が後の具体例で解けるか、節を移るときに次の話題が必要になる理由を追えるかを確かめる。仕様や手順の列挙に見える箇所では、読者が何を見てどう判断する場面かに戻って書く。抽象的な名詞や逐語訳のような語順は、元の意味を保ったまま、具体的な動詞と自然な語順に直す。

[語り口のレビュー](editorial-voice.md#初稿と改稿を通して読む)では、読者が前後の文から意味を追えるかを見て直す。自然な表現への言い換え後も、実測した範囲と説明用の例が区別できるか確認する。

具体例の後ろを見直すときは、[具体例の直後を読む](reading-experience.md#具体例の直後を読む)に沿って、実際の修正理由を残す。元の条件や操作の順序を伝えている記述は、一般則に見えても用途を確認してから編集する。
