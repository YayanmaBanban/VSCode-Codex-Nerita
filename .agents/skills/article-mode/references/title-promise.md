# Title Promise

タイトルは、読者が本文で得られる価値を示す。構成案の編集方針を決めるときに、同じ根拠から題名も設計する。次の型は題材に応じて使う例。

| 型 | 例 | 本文で届ける内容 |
| --- | --- | --- |
| 問題 → 行動 | AI が書いたコメントで差分が読みづらくなったので、日本語校正スキルを作った | 作った理由、どんな工夫を組み込んだか、使う場面の例 |
| 問題 → 方法 | 読みにくい日本語コメントを、Lint とコードの照合で見直す | 問題の見分け方と方法、その適用条件 |
| 発見 → 対応 | 誤った回数も Lint を通ったので、コードで条件を確かめた | 発見した根拠と、その結果どこを調べたか |
| 方法 → 成果 | JSONL を手掛かりに、日本語コメントを実装と照合する | 実行する操作、得られる結果、確認できる範囲 |
| 検証 → 結果 | コメントを3通り検査したら、誤った回数も通った | 比較条件、実際の結果、その解釈 |

候補ごとに題名の前半から対象か問題を推測できるか確認する。数字は記事の中心にある確認済みの値を使う。語尾、文字数、数字の有無を点数化しない。型の違いは、読者の疑問や本編の約束の違いで判断する。

1. 匿名レビュアーにまずタイトルだけを渡し、読者、何が起きたか、何をしたか、続きを読むと何を得られるか、分からない点を記録してもらう。
2. 記録後に[導入単独のレビュー](editorial-voice.md#構成を選ぶ前に)を行う。その回答を受け取ってから、匿名の構成と根拠を渡し、各タイトルの約束を満たす章と根拠を照合する。制作記録なら理由・制作した内容・例を、比較なら条件と結果を見る。曖昧で題材を推測できない場合や、導入から本文で知りたいことが見つからない場合も指摘する。
3. 採用する題名と構成を一緒に提示し、ユーザーの承認と関連付ける。題名の変更で主題や約束が変わるときは、その変更を承認へ差し戻す。自然な言い換えは同じ約束に照合する。

必要な場合は各案の `titleDesign` に `pattern`、`readerCue`、`promisedValue`、`curiosityLeft`、`risk` を保存する。承認された題名には `titleContract` を添え、`titleText`、`pattern`、`promise`、`mustDeliver`（必要な内容と対応する章）、`userApproved` を記録する。原稿レビューで約束が満たされなければ `type: "title-promise"` を使い、対応章と根拠を示す。

## 制作者と成果物を伝える

`brief.articleIntent.kind` と `authorMotivation` の出典を読み、自作した成果物の紹介、他者のツールの紹介、制作記録で何を約束するかを確かめる。自作が確認できる紹介では、何を校正するか、作った成果物の名前、特徴を出した案も比べる。「作った」は完成したものを示しやすく、「作ってみた」は試作や体験の語り口に合う場合がある。一般名詞だけでも、その記事で読者が対象を識別できるかで判断する。制作記録を掲げるなら、本文には動機と成果物の中身、実際の使いどころが要る。

`titleDesign` の `ownershipCue` と `artifactNameCue` には題名にある手がかりを記録できる。自作だという根拠がなければ制作を断定せず、成果物名を省くかどうかは、検索や識別のしやすさ、読みやすさで決める。確認済みの作者性が題名から伝わりにくい場合は `title-authorship` を提案する。選んだ題名と本文が届ける価値は `titleContract` で一緒に確定する。

## 制作物と具体例のどちらが主題か

自作したものを紹介する記事では、`articlePrimarySubject` と `exampleTopics` を読み、制作物、その価値、制作した背景が伝わる案を比較に含める。同じ原稿で制作物中心・技術的な特徴中心・具体例の疑問中心の案を比べられる。題名だけを読む独立審査で、何についての記事か、何を作ったと読めるか、読了後に何が分かると思うかを聞く。本文と根拠を開示してから、期待が `titleContract.promise` と、その約束を満たす章に対応するか照合する。

検索キャッシュの挙動を調べる記事なら「検索キャッシュはいつ消える？」で主題を伝えられる。日本語校正スキルの紹介で同じ題名がキャッシュの挙動を約束するように読めるなら、`artifact-focus-drift` とする。具体例の疑問は導入の一部や節見出しに置ける。「作った」の有無は、制作物と筆者の立場を本文と根拠で裏付けられるかで判断する。主題や約束を変更するときは既存の承認へ戻す。
