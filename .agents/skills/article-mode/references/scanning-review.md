# Scanning Review

記事の狙いと本文を用意し、次を本文の順序で別々のビューに抽出する。行番号や節名を控え、本文に戻る前にビューごとの一文要約と不足条件を書く。

| ビュー | 抽出するもの | 確認すること |
| --- | --- | --- |
| 見出し | 記事タイトルと本文の見出し | 論点、順序、結論を追えるか。抽象的な見出しが用途や条件を隠していないか |
| 強調 | 太字、リンクラベル、主張に関わる数値と単位 | 抜き出しても指す対象、否定、条件が読めるか。数値の根拠や測定対象が推測に変わっていないか |
| 段落冒頭 | 本文中の各段落の最初の一文 | 論旨を追えるか。結論や重要な前提が後続の文や折り畳みの内側に遅れていないか |

引用やコードの中の構文は本文の見出しと区別し、折り畳み内の要素には閉状態で見えないことを記録する。各ビューの要約を元の本文と比較し、誤読や欠落が生じた位置を特定する。修正案は元の主張・条件・確実性を保持する範囲で示す。

指摘は `location`、`problem`、`reason`、`suggestion`、`principleId` を持つ。`reason` には抽出した情報だけを読んだときに起きる具体的な誤読や不足を書く。解釈を模擬する評価として記録する。

見出しは目次での案内と、前後の文脈の両方で判断する。対象が明らかな「スキルの使い方」は自然な案内になる。依頼、修正、再検査などの操作が本文に残っているかも確認する。
