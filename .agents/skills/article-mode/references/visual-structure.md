# Visual Structure Review

## 作図する関係を選ぶ

工程、分岐、責務、依存、状態遷移、項目同士の対比を抽出する。各図について「読み手のどの疑問に答えるか」を一文で書く。同じ内容を短文や表で十分に追える場合は図を作らない。図の配置、元 SVG、回答する疑問、代替テキスト、キャプションを記録する。

## 静的 SVG のスタイル

- 編集元は自己完結した SVG とし、`viewBox`、`<title>`、`<desc>`、テキスト・図形・線を含める。JavaScript、外部リソース、アニメーション、`foreignObject` は使わない。作図できない環境では関係・ラベル・配置・代替テキストを含むブリーフを渡す。
- 余白の基準は 8 SVG 単位。ラベルと所属要素の余白は小さく、グループ間は広げる。例として内側に16、異なるグループ間に24を取る。配置と近接で階層を表し、読み順に合わせて矢印を引く。
- 背景は `#FFFFFF`、通常文字は `#172B3A`、工程の線や枠は `#35536A` を起点とする。強調する工程には `#E8F2FA` などの淡い面を使い、役割の違いは色に加えて線やラベルでも示す。通常文字は背景に対し4.5:1以上、関係の把握に必要な枠や線は隣接色に対し3:1以上にする。出典の利用条件を確認し、ロゴやブランドの意匠の転用は避ける。[デジタル庁デザインシステムの余白](https://design.digital.go.jp/dads/foundations/spacing/)・[カラーのアクセシビリティ](https://design.digital.go.jp/dads/foundations/color/accessibility/)
- 日本語の文字は描画幅を確認して明示的に改行する。スマホ幅で判読しにくい場合は縦に積むか、疑問ごとに図を分ける。SVG の重要な関係を本文キャプションと代替テキストからも読めるようにする。
- 外部の図解 Skill を利用するときは、実装・ライセンス・描画品質・静的 SVG 要件を確認してから採否を決める。どの媒体でも同じ SVG を編集元とし、PNG は掲載に必要な場合だけ派生させる。デジタル庁の素材を用いる場合は出典表示の条件も確認する。[デジタル庁デザインシステムの利用上の注意事項](https://design.digital.go.jp/dads/introduction/notices/)

## 検査

SVG をブラウザで描画し、実際のフォントが読み込まれた後に `getBoundingClientRect()` を測る。テキストとラベルの矩形が意図なく重なる箇所、文字が所属する枠や SVG の外にはみ出す箇所、線・矢印の描画範囲がラベルを横切る箇所を検査する。斜線の矩形が交わるだけの場合は誤検出になり得るので描画も見る。線と文字の実効色から相対輝度とコントラスト比 `(明るい側 + 0.05) / (暗い側 + 0.05)` を計算する。透過色を使う場合は合成後の色を測る。

PC とスマホの実表示幅、媒体のテーマでレンダリングする。線・矢印・文字の重なり、切れ、横スクロール、文字の判読性、キャプションと図の対応を画面で確認する。PNG 出力後は、並び順、矢印の向き、ラベル、キャプションが SVG と一致するかを確認する。プレビューや自動測定が使えない場合は、その検査を未実施として記録する。
