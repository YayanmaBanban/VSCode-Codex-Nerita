# React UI の実装

React UI の作成・変更時に参照する。既存のコンポーネント・テーマ・スタイルの構成を確認し、画面全体で表示と操作が揃うように実装する。Storybook に関する規約は、Storybook を使用する場合に適用する。

## スタイルの選択

- Tailwind CSS を配置・余白・文字サイズ・色・枠線などの通常のスタイルに使用する。
- 色や寸法は既存のテーマ定義・デザイントークンを利用する。同じ用途の既存トークンがある場合は、それを再利用する。
- テーマ定義・デザイントークン・テーマ適用処理は製品と共有し、Storybook 専用に値を複製しない。Storybook の Decorator は、製品の Provider や CSS 変数を適用するために使い、製品と同じテーマ切替を再現する。
- Tailwind のクラス名は完全な文字列で記述し、文字列の組み立てによって生成対象から漏れないようにする。
- 共通の基本スタイルや複雑なアニメーションなど、CSS でまとめた方が意図を読み取りやすい処理は CSS に残してよい。
- 既存 CSS から移行する場合は、重複する宣言とスタイルの優先順位を確認する。Tailwind の使用だけを理由に、見た目や操作を変更しない。
- Storybook 専用の CSS で製品コンポーネントのスタイルを再実装・上書きしない。背景・表示領域・配置など、利用環境を再現するためのラッパーは許容する。
- 製品と Storybook に表示差がある場合は、テーマ・スタイルの読み込み・ラッパーの条件を確認する。表示差の原因が共有方法にある場合は、製品側のテーマ・コンポーネント・レイアウトの共有方法を修正する。

## 実装時の確認

- 既存の UI コンポーネントや操作パターンを利用し、キーボード操作・フォーカス・無効状態を保つ。
- 狭い幅、長い文言、明暗テーマでも表示と操作が成立するようにする。
- UI コンポーネントと UI 側の状態管理・イベント処理・変換ロジックは製品と共有する。Storybook は初期状態や外部応答を設定し、製品ロジックを再実装しない。
- Storybook のモックは、ホスト環境・バックエンド・ネットワークなどの外部境界に限定し、製品と同じ型・インターフェースを通して接続する。
- Storybook 専用のモック・サンプルデータ・検証データは製品コードから分離する。
- Storybook での表示・操作確認と、実バックエンドとの接続検証は分ける。Storybook のモックだけで実バックエンドとの互換性を保証しない。

### JSX / Tailwind CSS の可読性

- 短い静的な `className` はそのまま記述する。
- 1行で読みづらくなる長い Tailwind CSS のクラス列は、`cn()` を使って意味のあるまとまりに分ける。
- `cn()` の各引数は、レイアウト・サイズ・余白・外観・テキスト・状態など、関連するスタイルをひとまとまりにする。これらは分類の例であり、固定の引数順や全分類への分割を求めない。
- 1クラスずつ引数へ分割しない。1つのまとまりが短い場合は、無理に分割しない。
- 条件によるクラスの切り替えや外部 `className` との結合には `cn()` を使う。
- `hover:`・`focus:`・`disabled:` などの状態やレスポンシブ指定は、対応する基本スタイルとの関係が読み取れるようにまとめる。関連するスタイルの近くに置くか、状態・画面幅ごとにまとめる。
- `cn()` に分けてもスタイルの意図が読み取れない場合は、コンポーネントの責務やスタイル設計自体の分割を検討する。
- JSX が大きくなった場合は、コメントで区切るより意味のある UI 単位をコンポーネントへ分割する。行数だけを理由に、小さな JSX を過剰にコンポーネント化しない。
- この規約に沿う範囲で、既存コンポーネントや周辺コードの書き方に合わせる。

`cn()` は `cnfast` からインポートする。

```ts
import { cn } from "cnfast";
```
