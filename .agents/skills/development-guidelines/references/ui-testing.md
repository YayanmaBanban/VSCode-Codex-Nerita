# UI テストの実装

Storybook・Playwright・UI モック・UI テストの変更時に参照する。

共通の可読性・アサーション・モック方針は [テスト共通ルール](testing-common.md) を参照する。確認済みなら再読は不要。

## 通信境界と実環境

対象プロジェクトのテスト設定と既存のモック API を確認する。実 UI の操作、送信内容の確認、固定応答の注入、応答後の表示・操作可否の確認を分ける。モック内に承認・認証・保存などの製品処理を再実装せず、送信値を補正しない。応答前・成功後・失敗後の必要な状態を明示する。

実環境の受入では画面操作や公開 API を使い、製品状態の直接書換えで操作を代替しない。外部応答を代替する範囲はプロジェクトの検証契約に従う。表示だけでなく保存内容や副作用も観測する。

生成物・一時領域・プロセスは実行ごとに分離する。準備失敗や結果未生成を成功扱いにしない。終了・期限切れ時は専用プロセスを回収する。要素の役割や名前で操作し、対象状態の成立を待つ。
