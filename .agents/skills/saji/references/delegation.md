# サブエージェント

**親エージェントの責任。** `saji`を受け取ったチャットがPlaybookを実行し、ToDoを管理し、委譲先の成果をレビューする。ワーカーは作業前に`worker.md`を読む。

**固定名エージェントの選択。** 現在の実行環境で対象タスクに合う固定名エージェントが定義されていれば利用する。なければ実行環境で利用できる別のエージェントを選ぶ。エージェント起動機能がない場合は、当該Playbookが許す場合に限り親が実装を担当して別のレビュー工程を設ける。独立した評価者が必須で代替できない場合、その工程を完了扱いにせず停止する。存在しないエージェント名、ツール引数、モデル識別子を捏造しない。

**モデルの選択。** まず起動可能なモデルと推論設定をツール定義で確認する。モデルを個別指定できないなら親のモデルを使用する。モデルIDや推論強度を推測して渡さない。複数の提供元を必要とする評価では、実際に異なるモデル系列を使えない限り同等の評価ができたと主張しない。

**ワーカー起動文。** ワーカーにファイルアクセス権があることを確認する。先頭行は`Read <path>/worker.md before anything else.`とし、`<path>`はこのSkillフォルダの絶対パスとする。目標、担当範囲、対象ファイルとデータ構造、検証条件、参照するファイルのパスを伝える。ワーカー自身が読める大きなファイル内容は、依頼文へ大量に埋め込まない。

**最終的な責任は親にある。** サブエージェントの差分を確認し、自身の言葉で結果を報告する。別の提供元のモデルによるセカンドオピニオンは、同じ依頼文を渡して得る。

**原則、新しいサブエージェントを起動する。** 修正ラウンド、追加指示、再試行、次の待ち行列の項目には、元の依頼文、その後の全指示、前のエージェントの報告とブランチを渡して新しいエージェントを起動する。既存のエージェントを再開するのは、そのエージェントのチェックアウト、未コミットの変更、実行中のプロセスなど、移動コストの高い状態がその中にある場合だけとする。
