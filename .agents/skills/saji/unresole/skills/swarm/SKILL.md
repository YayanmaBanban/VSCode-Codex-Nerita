# Swarm

## 開始（Start）

何かを起動する前に、各フェーズに1項目ずつ対応するToDo一覧を作成する。

1. Frame
2. Fan out
3. Aggregate
4. Report

## フェーズA：条件の定義（Frame）

1. 完了を判断する条件と、Swarmが返す成果物または報告を明示する。
2. 実行の構成を選ぶ。範囲を部分に分割する、同じ依頼文でN人を競争させる、または両者を組み合わせる。競争または組み合わせでは、起動前に`first pass`、`rank all`、`best-of`のいずれかを宣言する。
3. `~/.cursor/rules/pstack-models.mdc`の`swarm workers`行からワーカーモデルを選ぶ。規則またはその行がなければ`claude-opus-5-5-high-fast`を使用する。`auto`または`inherit-parent`の場合は`model`を省略し、親のモデルを使わせる。`Task`ツールがモデル識別子を拒否したら既定値を使用し、その旨を報告する。既定値も拒否された場合は、エラーメッセージにある同じ系列の最も近い有効な識別子を使う。モデルを競争させる場合は、各担当のモデルを事前に挙げる。各サブエージェントの推論レベルは**poteto-mode** SkillのSubagentsセクションに従って選ぶ。
4. ワーカーがファイルへ書き込む場合は、ワーカーごとに独立した書き込み先を与える。コミットを検証・計測する場合は、依頼文に正確なSHAを記載する。計測の場合は方法（サンプル数、1サンプルが表すもの、順序）も記載する。ワーカーはSHAと方法の両方を結果に記録する。

## フェーズB：並列実行（Fan out）

一つのメッセージでN人すべてのワーカーを起動する。`subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`と、手順3のモデルを使用する。`auto`または`inherit-parent`ではモデル指定を省く。ユーザーのコンピューター上にあるものへのアクセスが必要な場合に限り`environment: "local"`を使う。

ワーカーを既定以外のPush済みブランチから開始する必要がある場合は、`cloud_base_branch`を渡す。

各依頼文は単独で内容が完結するようにする。目標、範囲、担当する正確な部分または競争する案、検証方法、報告事項を含める。結果は証拠付きで`PASS`、`ISSUES`、`BLOCKED`のいずれかを使う。不具合を証明できたワーカーは`ISSUES`とし、最初の1件だけでなく証明できたすべての不具合を列挙する。

ワーカーが脱落した場合はN-1件で続行し、脱落を記録する。

## フェーズC：集約（Aggregate）

最終結果を読む。依頼文で指定したSHAと方法を記録していない結果は破棄し、そのワーカーを1度だけ再起動する。再度欠けていれば未確認の範囲として記録する。未確認の範囲を合格として扱わない。網羅確認では必要な部分すべてに結果が必要。競争の場合は、事前に宣言した`first pass`、`rank all`、`best-of`を適用する。ワーカーの生出力をそのまま貼り付けない。

## フェーズD：報告（Report）

結果の表、不具合の一行概要、未確認の範囲や脱落、使った場合は競争の選択規則を含めた、統合済みの報告1つをチャットで返す。
