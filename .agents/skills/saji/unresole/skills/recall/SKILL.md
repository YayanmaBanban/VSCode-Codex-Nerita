# Recall

**作業開始・再開前に、ユーザーの最近の作業文脈を再構築し、現在地と次の行動を短くまとめて返す。**

対象を絞り、簡潔にする。対象となる作業のために必要なものだけを読み、そこで止める。

文脈は2種類の記録に存在する。自分のチャット履歴には自分が行った作業と判断がある。共有された記録には、同じコードをめぐって別の名前で発生したすべてのことがある。ユーザーが繰り返し報告する症状、出荷後に取り消された修正、本番でまだ発生するエラーなどである。共有の記録はソース管理、課題管理、チャットと課題のチャンネル、詳細な文書、エラー追跡にある。長いバグ履歴を持つ機能では、その経緯の大半が共有の記録にあるため、自分のトランスクリプトだけから復元しない。

トランスクリプトは`~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`にある。`<slug>`はワークスペースのパスから先頭のスラッシュを取り除き、各「/」を「-」にしたもの（`/Users/you/proj`なら`Users-you-proj`）である。1行がチャットの1メッセージに対応する。

1. まず分類して振り分ける。特定の過去チャット1件を再開する場合はこのSkillではなく`session-pickup` Playbookを使用する。習慣を永続的なSkillにする場合は`automate-me`。人間向けに作業を要約するのは別のタスク。Recallは次の行動前に最近の複数チャットから作業文脈を読み込む。ユーザーがパス・ブランチ・変更を含む完全な状態の要約を渡している場合は、それを使い、履歴の発掘は省略する。
2. 検索前に対象範囲を確定する。期間（「最近」は具体的な期間で、既定は直近7日間）、指定された話題、ワークスペース（既定は現在のもの。依頼されない限り別プロジェクトのトランスクリプトを読まない）を固定する。範囲をユーザーに言い直す。「すべて」を黙って「最近N件」に変更しない。
3. チャット履歴を並列に調べる。高速・低コストのモデルでサブエージェントを複数起動し、記録の各部分を担当させる。候補はUUID名ではなく実際の更新時刻（`ls -t`）順に並べ、先に話題をgrepし、一致したチャットの関連箇所だけを読むよう依頼する。現在のチャットと明白なノイズ（サブエージェント、Eval、テストのチャット）は除く。各担当は同じ形式で、チャットごとに話題、ユーザーの目標、判断、未完了の論点、困難と訂正、成果物（PR・チケット・ブランチ）を、チャットUUIDとともに返す。1～2件なら並列化せず直接検索する。生のトランスクリプトはサブエージェント側に置き、親スレッドへは調査結果だけ渡す。各担当の推論レベルは**poteto-mode** SkillのSubagentsセクションに従う。
4. 話題に機能、ファイル、サブシステム、領域、不具合の名前がある場合は、共有記録を必ず調べる。これは既定の処理であり、判断で省略しない。「Xについての自分の作業」でも例外としない。記録元ごとに調査用サブエージェントを1人起動する。読み取り専用モードはMCPアクセスを外すため、エージェントモードで起動する。各担当には「現在の状態、試したが解決しなかった方法、ユーザーがまだ報告している症状」を調べさせる。チャット履歴の調査と並列に実行する。何も見つからなかったことも結果とする。利用できないMCPは省略し、その旨を伝える。話題がない純粋な活動履歴の振り返り（「今週何をした？」）では、本人の履歴と現在状態だけで回答できるため、この工程を省略する。
5. 実際の現在状態と照合する。履歴調査から見つかったPR・ブランチ・チケットを`git`と`gh`で確認する。エージェントが実際に使ったツール、読んだファイル、遭遇したエラーなどの行動に回答が依存する場合は、短縮されたローカルコピーではなくトランスクリプト全体を読む。
6. 以下の形式に従って短い報告を書く。作業の流れごとにまとめ、指定された話題から外れない。

## 出力の契約

最初に全体の要約、次に作業の進捗、問題、次の行動を示す。詳細は下に置くか削除する。

- **全体の要約（Capsule）。** 最大5項目。この作業の内容と全体の現在地。
- **進行中の作業（Threads）。** 1件1行。先頭に次のステータスタグを正確に1つ付ける。`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]`、`[planned, not started]`。タグなしの作業を残さない。
- **問題（Problems）。** 最大5件。繰り返す問題を優先する。ユーザーが継続して報告する症状と、出荷後に取り消された修正を含め、次の試行が以前の失敗地点から始められるようにする。
- **次の行動（Next move）。** 最も有用な次の具体的な行動1つ。

隣接する機能やチケットは対象作業を妨げる場合以外、含めない。全体の要約と進捗行が1画面に収まらない場合は、作業を削る前に詳細を削る。報告には**unslop** Skillを適用し、チャット由来の結果はUUID、共有記録由来の結果は資料（PR番号、チケットID、チャットへのリンク、エラー追跡の課題）を挙げて根拠を示す。公開出力にする前に非公開の文脈を除去する。

**回答：** 上記の契約に従った報告。
