# Architect

コードを書く前に、変更が触れるすべてのシステムを追跡する。その後、型・シグネチャ・モジュール境界について異なる2つの構造案を描き、各状態の所有者が1つで、各タスクの実行方法が1つであり、呼び出し側が知る必要のあることが最も少ない案を選ぶ。回避策が繰り返される場合は、継ぎ足しの修正ではなく再設計する。

大規模な設計や見解が対立する設計では、一人で案を描く代わりに**arena** Skillを実行する。
