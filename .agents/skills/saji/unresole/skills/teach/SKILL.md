# Teach

**対象が何で、どう動き、なぜそのように作られたかを、相手の理解の速さに合わせて一つの平易な説明にする。目的は理解してもらうことであり、何かを変更することではない。**

Teachは`how`と`why`の上に構成される。最初に仕事の内容と影響範囲を把握し、次に動作の仕組みを知るために`how`を、理由を知るために`why`を実行する。これらは実際に別の調査を行うSkillの呼び出しである。両方の結果を一つの平易な説明へ統合し、相手に重要なことから始め、質問に応じて深める。教えるためなら自由に言い換えてよいが一つだけ例外がある。`why`の確信度を示す表現は変更しない。そこでの留保は文章の癖ではなく、調査結果だからである。

1. 最終的に理解してもらうべき少数の点を決める。なぜ尋ねているか（変更前、レビュー中、デバッグ中、初めて触れるなど）と、すでに知っていることを会話から読み取る。知識を試す質問はしない。明らかに知っていることは省き、質問に合う部分を深く扱う。
2. `how`と`why`に調査を任せ、自分でやり直さない。まず自分でコードを読んで方向を掴み、その後、`how`で動作を、`why`で理由を調べる。両方を並列に実行し、結果を統合する。調査量は質問に合わせる。サブシステムなら両方、小さな変更なら片方で足りることもある。
3. 平易な定義から始める。対象の名前と、それが一般に何なのかを、シニアエンジニアが口頭で話すように説明する。一般的な呼称があれば添える。続いて目前の事例（「Xではこれを…のために使う」）と結び付け、仕組み、より深い理由、例外へと進める。各部分では解決する問題と実際の仕組みを説明し、理解できる形にする。長いチャットを開いて上へスクロールする場合など、実際の操作順が理解を助けるなら、その間に起きることを順にたどる。関数や定数の一覧はリファレンスであり、教育ではない。「覚えるべき一つのこと」「持ち帰ること」「重要な気付き」「本質的には」「TL;DR」などの枠組みを示すラベルは出力しない。最初は完全性を保てる最小の答えを、密な段落ではなく1～2文で示して停止する。質問があれば層を重ねる。大量の文章を一度に出さない。
4. 講義や演出ではなく会話にする。より深く調べるか次へ進むかを提案し、相手に合わせる。小テストはしない。理解の速さを演出しない。「Pause」と表示せず、復唱させず、「ここで覚える一文」などと宣言せず、「ここは少しゆっくり」「ここが難しい」「ここから面白くなる」といった重要度や難易度の演出をしない。ただ説明する。区切るべきところでは話すのを止め、相手の反応を待つ。人間がその場にいない一括実行では、説明をきちんと届け、深掘りの提案があれば最後に置く。
5. 言葉だけではなく見せ、図を一つずつ増やしながら組み立てる。差分、コード、デバッガーを開く方が早く理解できるならそうする。図の方が早く伝わる場合は描く。動く部分が3つ以上ある場合、最初から全部入れた図を1枚描かない。短い図の連続にして、直前の図を描き直し、要素を一つずつ加える。読み手がシステムの組み立てを追えるようにする。最後に置くだけの一枚の全体図は、解説の資料ではあっても教育にはならない。A→B→Cの流れを教えるなら3回描く。まずAからB、次にCを追加、最後に戻る矢印か次の要素を追加する。考え方に合う媒体を選び、両方役立つなら併用する。ラベル自体が意味を伝える流れや構造にはMermaid図が合う。レイアウト、重なり、スクロール位置、前後比較など空間的な内容には画像生成ツールを使い、短いラベルを少数付けたホワイトボードのマーカー描き風の図を生成する。画像モデルは長文を崩しやすいためである。画像を生成し、言葉による説明だけで済ませない。生成画像でも一つずつ要素を加える規則を守る。単純な点一つなら図は不要。

すべての回答に**unslop** Skillを適用し、同僚に説明するような平易な口語の英語で書く。短くするが、省略しすぎない。無駄な言葉と留保を減らし、理解につながる部分を残す。比喩、枠組み、予告ではなく、具体的な仕組みを述べる。求める情報密度は「Virtualizationは描画とディスクからの読み込みの2つに分かれて動く。項目がバッファより外へスクロールすると、そのDOMノードとメモリ上のデータの両方が破棄される」という程度である。すべて小文字ではなく通常のsentence caseを使う。em dashを使わずコンマよりピリオドを優先する。1文のコンマは1～2個に抑える。節が積み重なれば文を分ける。一つの概念には一つの名前を使い続ける。「A without B, or B without A」のような鏡合わせの文、「the rest follows」「it all falls out」のような整いすぎた結びを避ける。これらの工程の文章はエージェントへの指示であり、出力するラベルではない。構造をそのまま見出しや定型句として繰り返さない。

**回答：** 実施報告ではなく説明そのものを返す。最初に要点を述べ、その後に対象が何か、どう動くか、なぜそうなのかを平易に説明し、さらに追う価値がある`how`・`why`の話題を示す。
