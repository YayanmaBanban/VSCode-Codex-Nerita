# TypeScriptのベストプラクティス

まず**type-system-discipline** Principleを適用する。

| 規則 | 要約 |
| --- | --- |
| 判別可能なUnion | `kind`のリテラル値を判別子としてバリアントを表現し、不可能な状態を作れないようにする。省略可能なフィールドを詰め込んだ型を使わない |
| ブランド付き型 | プリミティブ型へ`& { readonly __brand: "X" }`を追加し、取り違えを防ぐ。境界で一度検証する。ブランドは検証を行う型ガード（`input is AgentId`）から生み、`as`によるキャストでは作らない |
| 構築によるモデル化 | 不正な値を構築できないデータ形状にする。空でない配列には`[T, ...T[]]`、偶数長の組には`[T, T][]`、範囲には`start`と`duration`を使う。実行時ガードでも、リファインメント型への期待でもない |
| 最も単純な全域型 | すべての操作が全域的に定義できる限り`T[]`を維持する。緩い型が`!`、キャスト、または「起こるはずがない」というthrowを強制する箇所に限り`NonEmpty<T>`へ強める |
| `any`より`unknown` | 外部データは`unknown`とする |
| ガードよりスキーマ | プロパティごとの型ガードを手書きする前にリポジトリの実行時スキーマライブラリを使い、`z.infer`などで型を導出する |
| `as`キャスト禁止 | `as`は実行時クラッシュの危険を伴う。検証後だけキャストする |
| 型の絞り込み順 | 判別子のswitch ＞ `in`演算子 ＞ `typeof`／`instanceof` ＞ ユーザー定義型ガード ＞ `as` |
| 型ガード | 主張する内容を実際に検証する。嘘をつく型ガードは、安全を示す名前の背後へバグを隠すため、`as`より悪い。`isX`または`hasX`と命名する |
| 網羅性 | default節に`const _exhaustive: never = x;`を直接置き、新しいバリアントが増えたらコンパイラーがエラーを出すようにする |
| `as`より`satisfies` | リテラル型を広げずに値を検証する |
| 境界での検証 | データが入ってくる境界で解析し、名前付きのドメイン型にする。`Record<string, unknown>`は、どのような記法でも、その解析を越えて広げない。内部では型を信用する。**boundary-discipline** Principleを参照 |
| スキーマからの型導出 | 新しいinterfaceを作る前に`Pick`／`Omit`／`Parameters`／`ReturnType`／`Awaited`／`typeof`を検討する |
| オブジェクト引数 | 順序が自己説明的になるよう位置引数ではなくオブジェクトを渡す。ただしホットパス（フレーム単位の描画、トークナイザー、パーサー）では省略する |
| 実物を用いたテスト | 実際に動かせるものをモックにしない。フレームワークの実際のテスト機能とリーク・dispose検査を優先し、実行中のビルドでUIを検証する。ローカルで実行できないものだけをモックにする |
| 構造化された診断ログ | IDから調査できるだけの文脈を持つ構造化ロガーを優先する。出荷コードに`console.log`を残さない |
