# ドメインを構造として表現する（Model the Domain）

ドメインの規則を条件分岐へ散らす代わりに、データ構造で表現する。適切な構造を選べば不正な状態を表現できなくなり、分岐が減る。

散在する真偽値やフェーズ判定の代わりに状態機械、曖昧な引数の代わりに型付きモデル、ファイル間に散る分岐の代わりにMap・レジストリ・判別可能なUnion、場当たり的な変更の代わりにreducerを検討する。アクセスパターンに必要ならインデックス、キュー、正規化されたコレクションを使う。

無理に適用しない。構造が明瞭で局所的であり、拡張も想定されない普通のコードはそのまま残す。分岐や不正状態を減らさずに間接参照だけ増やす抽象化は疑う。

省略した兆候：機能を追加するたびにif/elseの分岐が一つ増える、または最初の真偽値と同期して維持しなければならない2つ目の真偽値が現れる。
