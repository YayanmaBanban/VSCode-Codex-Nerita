### Worktreeと一時実行環境の整理（Worktree and simulator cleanup）

**削除前の確認と権限が必須。** worktree・一時ファイル・シミュレーター・キャッシュの削除には、対象のパスやデータ種別を含むユーザーの明示的な許可が必要。分類結果の`safe`表示だけで削除しない。

1. **状態を記録して監査する。** ディスク空き容量はWindowsなら`Get-PSDrive -PSProvider FileSystem`、Unix系なら`df -h /`で記録する。`git worktree list --porcelain`から実在するworktreeのパスを取得し、パスを推測して補わない。各パスについて`git -C <path> status --porcelain=v1 --untracked-files=all`、現在のブランチ・HEAD、`git log -1 --format=%cI`を取得する。PRの対象ブランチが分かれば`git merge-base --is-ancestor <head> <base>`でマージ済みか確かめ、`gh pr list --state all --head <branch>`でPRの状態を確認する。容量は利用可能なディスク使用量ツールで測る。容量・経過時間・マージ状態・未コミット作業・PR状態・現在使われているセッションを表にし、削除候補を分類する。
2. **分類結果を削除許可と混同しない。** ピン留めや進行中のチャットがどのworktreeを使用しているか、現在のワークスペースに紐付くセッションの情報で確認する。セッション情報が取得できなければユーザーに該当する一覧を確認し、不明の対象は保留する。ピン留め・利用中という実際の情報を、ツールの`safe`判定より優先する。
3. **削除候補の利用状況を調べる。** 最近使用したチャットとの関係が不明なworktreeは、現在のワークスペースで利用可能な実際のセッション記録から確認する。大量の記録はサブエージェントへ読み取り専用で分担できるが、無関係なプロジェクトの記録は調べない。主チャットから作った並列実験用・再現用の兄弟worktreeも使用中の可能性がある。参照先が分からない場合は削除候補から外す。
4. **未コミット状態と消失リスクを判断する。** `wip:N`はGitで追跡中の未コミット変更N件、`scratch:N`は未追跡ファイルN件とする。未コミットの差分は削除で失われ得るため、差分とファイル名を提示しユーザーの判断を得る。未追跡ファイルも名前と必要性を確認し、使い捨てという推測だけで削除しない。マージ済み・作業ツリーがクリーン・どのセッションも使っていないことが揃っても、対象パスを含む削除許可を得るまでは実行しない。
5. **許可された対象だけを削除し、結果を確認する。** 対象パスとブランチを再確認したうえで`git worktree remove <path>`を実行する。`--force`は未追跡・無視ファイルの消失を起こすため、残存ファイルを列挙して個別に許可された場合に限る。追加のディレクトリ削除は内容を確認して別途許可された場合だけ行う。必要なら`git worktree prune`で不要になったworktree管理情報を整理する。ブランチ参照は削除しない。ディスク空き容量と`git worktree list`を再取得して差分を示す。
6. **シミュレーターやほかの容量回収対象を確認する。** 現在の環境に該当するツールと対象がある場合だけ調査する。macOSでXcodeシミュレーターの利用が確認できた場合は`xcrun simctl list`などで状態を調べ、削除候補を列挙する。WindowsでXcodeの`simctl`を実行しない。Xcodeの`DerivedData`、デバイスサポート、pnpm・uvなどのパッケージキャッシュも、既存の用途・残すべき内容と回収効果を確認してから、対象と削除許可を明示する。依頼されていないユーザーデータを勝手に消去しない。

このPlaybookはコードレビューで事故を検出できないデータ削除を扱うため、各削除前の実データ確認と承認がレビューに相当する。

**回答：** 取得できたディスク空き容量の前後値と回収量、削除済みworktree、保留した対象とその具体的な理由（利用中のセッション・未コミット変更・権限不足など）を報告する。
