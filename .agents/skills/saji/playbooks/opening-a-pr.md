### PRの作成（Opening a PR）

ほかのPlaybookのPR作成工程から呼び出される。ただし**ユーザーがPR作成を明示的に許可している場合だけ**実行する。許可がなければ差分と検証結果を提示して停止する。

trunkから分岐した独立したGit worktreeで作業し、無関係な変更を含めない。コミットとリベースがそれぞれ許可されている場合だけ、小さくマージ可能なコミットへ整理する。コミット前には`git diff --check`を実行し、プロジェクトで定義済みのLint・フォーマット・型チェック・関連テストを確認する。また、冗長な実装、不要なコメント、説明文の重複、場当たり的な回避策が残っていないか差分をレビューする。

タイトルは`type(scope): subject`形式とし、変更を代表する実際のシンボルがあるならそれを含める。本文は40行未満で、1分程度で把握できる説明にする。見出しは`##`形式で、`## Why`、`## What changed`、`## Scope`、`## Tradeoffs`（レビュー担当が尋ねそうな不採用案だけ）、`## Blast Radius`、`## Verification`の順とし、空の節は除く。

後続変更は依存先のベースブランチを設定してスタックする。`gh --version`とGitHubへの認証を確認したうえで、PR作成が許可されている場合だけ`gh pr create --base <base> --head <branch> --title <title> --body-file <body-file>`を使う。作業が未完成なら`--draft`を付け、レビュー可能な状態であれば付けない。実行後は`gh pr view`でベースとhead、公開状態を確認する。PRの作成だけでBabysitを開始したことにはならず、マージ権限も得られない。
