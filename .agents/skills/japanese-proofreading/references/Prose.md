# 文章の校正

README、利用ガイド、SKILL.md、技術仕様書など、章立てのある文書の文章と構成を校正するときに適用する。
文書固有の検査ルールがある場合は別途併用する。コードコメントや UI 文言へ、この文書の構成校正を一律には適用しない。

読者が必要な情報を見つけ、正しく理解し、操作・判断・検証に使えるよう文章を整える。
文字数を減らすこと自体を目的にしない。
文体・情報の配置・表やリストの形式は変更できるが、元の意味や確実性は変更しない。

## 判断の基準

### ISO 24495-1:2023：プレインランゲージの4原則

[ISO 24495-1:2023](https://www.iso.org/standard/78907.html)を参考に、次の観点で校正する。

|原則|校正時に確認すること|
|--------------|--------------------------------------------------------|
|Relevant|読者の目的に必要な情報が揃い、不要な説明が妨げていないか|
|Findable|見出し・順序・表などから、必要な条件や手順に到達できるか|
|Understandable|主体・対象・前提・条件・結果の関係を理解できるか|
|Usable|読者が説明を使って、操作・判断・検証などを行えるか|

先に文書の読者と用途を確認する。すべての文書に同じ章立てを強制せず、必要な情報を削って短くしない。

### ISO 24495-3:2026：科学的な内容を説明するときの補助指針

[ISO 24495-3:2026](https://www.iso.org/standard/86938.html)は、背景知識の異なる読者に科学的な内容を伝える文章を対象とし、ISO 24495-1 を基礎とする。
科学的・技術的な主張、調査結果、測定、比較などがある文章では、次の観点も重視する。
通常の操作説明や SKILL.md に、科学的な説明を無理に追加しない。

|観点|校正時に確認すること|
|----------|------------------------------------------------------------|
|根拠と主張|観測された事実、推測、判断、推奨を混同していないか|
|不確実性|未検証、測定条件、適用範囲、限界を隠していないか|
|専門用語|必要な名称を維持し、読者が理解するための説明があるか|
|前提条件|比較対象、測定環境、期間、単位などが必要な場所にあるか|
|図表|値・単位・条件・出典・注記が対応しているか|
|正確さ|要約や校正で因果関係・確信度・効果を原文より強くしていないか|

各項目は文章校正へ応用した判断基準であり、規格の条項や準拠・認証の判定基準とは扱わない。
Lint の文字数閾値を ISO の要求値と説明しない。

## 文章と構成の校正

文章を直す前に、読者がその文書で知りたいこと、実行したいことを把握する。
長い段落や複雑な説明は、内容の関係が分かる形へ整理する。Lint が指摘しなかった箇所もレビューする。

|元の情報|適した表現|
|--------------------------|----------------------------------|
|独立した処理を複数含む文|文や段落を分ける|
|条件と結果、判断と対応の組|条件・対応・例外などの表|
|同じ軸で比較する選択肢|比較軸を揃えた表|
|時間・依存関係のある手順|順番を保った番号付きリスト|
|並列の確認項目・制約|箇条書き|
|複雑な背景と詳細|概要と詳細に分ける|
|繰り返される共通の説明|実在する共通文書への参照に整理する|

条件と結果が対応する場合は表にする。
表やリストへの変換、見出し・段落の再配置は、元ファイルへ直接反映する。提案だけで終了しない。
ただし、意味のある文章を機械的に表へ変えたり、並列条件に架空の実行順序を付けたりしない。

手順と確認項目は分ける。処理の順序は番号付き手順で示し、照合する値や判断基準は別の表や箇条書きにまとめる。
見出しを改めた場合は目次・アンカー・参照リンクを、共通文書へ整理する場合は参照先と適用範囲を確認する。出典や例外も残す。

## 再構成後の情報と意味の検証

表・リストへの変換や文章の統合後は、原文と照合する。

|確認する観点|原文と照合する内容|
|--------------|------------------------------------------------------------------------|
|網羅性|条件、処理、結果、例外、禁止事項、重要な補足が残っているか|
|列の一貫性|表の各行で同じ項目を比較しているか。特定の行だけ値や対応が欠けていないか|
|記述間の整合性|手順、表、補足文で同じ対象に矛盾する指示を出していないか|
|条件付きの処理|一部だけに適用する処理を、全件必須に変えていないか|
|正確さ|原文の判断主体、前提、確実性、実装状況、依存関係を維持しているか|

欠落や矛盾があれば、根拠となる原文や関連文書を確認して修正する。根拠がない情報は推測で補わず、未解決事項として報告する。
構成校正の完了前に、原文との意味の一致を再確認する。

README の動作例・コマンド、SKILL.md の呼出条件・禁止事項・フロントマターなど、機械や他の処理が参照する内容は変更しない。
校正作業の経緯、Lint の実行結果、変更件数などは、対象文書へ追加せず、校正完了時の報告に記載する。

## 校正ワークフロー

### 1. Lint・文章校正

1. 依頼された対象・読者・用途を確認し、修正前の内容を差分比較できるようにする。
2. [変更ファイルのコマンド](Cmd-Changed.md)または[全体・指定範囲のコマンド](Cmd-All.md)に従う。対象に応じて `textlint:review:changed` または `textlint:review` を実行する。
3. Lint とレビュー用データを読み、検査処理の失敗と文章への指摘を区別する。原文・周辺内容と照合し、文法・表記・冗長表現・長文を校正する。
4. 校正を元ファイルへ直接反映する。警告を消すための機械的な言い換えはしない。

### 2. 構成レビュー・直接校正

1. 文書全体の情報の順序、見出し、説明の重複、見つけやすさを確認する。
2. 説明が複雑な箇所や、条件・手順・比較を探しにくい箇所は、段落の分割、表・リストへの変換、見出しや説明順の変更で整理する。
3. 編集結果を元ファイルへ反映し、[再構成後の情報と意味の検証](#再構成後の情報と意味の検証)を実行する。

### 3. 再検査・最終確認

1. 選択したコマンド手順に従い、同じ対象へ `textlint:changed` または `textlint` を再実行する。
2. 修正差分を原文と照合し、意味・条件・参照・確実性が保たれているか確認する。
3. Markdown の表・見出し・リスト・コードブロックなどの構文を確認する。利用可能なら表示プレビューも確認し、問題があれば修正と再検査を繰り返す。
4. 修正内容、検査結果、意図して残した指摘、未解決・未確認事項を簡潔に報告する。

文章校正だけで終了せず、構成レビューまで実施する。通常の実装、`pnpm check`、`pnpm lint`、CI へ必須工程として追加しない。
