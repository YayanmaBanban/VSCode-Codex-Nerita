## 対象と実行方法

- [校正ルール](references/Proofreading.md)を読み、静的検査だけでなく説明と実装の一致を確認する。
- README・設計文書などの校正では[Markdown 文書のルール](references/Markdown.md)も読む。
- 変更分の校正には[変更ファイルのコマンド](references/Cmd-Changed.md)を読む。
- 全体や指定範囲を変更状態に関係なく校正する場合は[全体・指定範囲のコマンド](references/Cmd-All.md)を読む。
- 範囲の指定がなければ未コミット変更を対象とする。コミット済みの変更や特定の機能が対象なら、差分から対象ファイルを選び、引数で指定する。
- `--changed` は対象を指定しなければ HEAD との差分と未追跡ファイルを選ぶ。変更行だけでなく選択したファイル内の文章を抽出するため、修正範囲は依頼と差分に照らして判断する。

このスキルには、`private` を設定した Node.js パッケージが含まれる。依存関係は本リポジトリの pnpm ワークスペースで管理する。

依存関係が未導入の場合は、配置に応じてインストールする。

- 本リポジトリ内で使う場合は、リポジトリルートで `pnpm install` を実行する。
- スキルを単独でコピーした場合は、コピー先のスキルディレクトリで `pnpm install` を実行する。

パスは次の基準で指定する。

- `--root` の相対パスは、コマンド実行時の作業ディレクトリを基準にする。
- `pnpm --dir` を使う場合は、スキルのディレクトリからのパスを指定する。
- 対象ファイルの引数は `--root` を基準に解決される。

スキルを別の場所に配置した場合は、配置に合わせてパスを調整する。

設定と検査対象は次のように扱う。

- 設定と依存関係はスキル側から読み込む。
- 対象固有の `.textlintignore` と `.textlint-cache/` は対象リポジトリ側に配置する。
- `.git/`・`node_modules/`・`.textlint-cache/` は常に検査から除外する。
- リポジトリ外のパスとシンボリックリンクは検査対象に指定できない。

## 校正と完了

1. 選択した手順でレビュー用データを生成し、JSONL と検査結果を読む。文章への指摘か実行エラーかは、終了コードだけで判断せず、出力も確認する。実行エラーの場合は原因を解消してからレビューする。
2. JSONL の `file` と `startLine` を使って元の文章と周辺コードを読む。識別子・固有名詞を機械的に翻訳せず、実際の処理を自然な日本語で説明する。
3. 指摘のない文章も依頼範囲で確認する。修正前後の意味・重要度・確実さ・文の役割を照合する。校正に合わせて製品の動作を変更しない。
4. 変更ファイルの手順なら `textlint:changed`、全体・指定範囲の手順なら `textlint` を同じ対象に実行する。これにより静的に検査し、対応する古いレビュー用データを削除する。
5. 校正した範囲、修正内容、検査結果、未解決・未確認事項を簡潔に報告する。静的検査の成功だけで意味の確認を済ませたと扱わない。

校正は依頼時に実行する。通常の実装完了条件や `pnpm package` にこの手順を追加しない。

## 候補ファイルと一時データの扱い

候補ファイルに保存する指摘のまとめ方は、指摘の種類によって異なる。

- `unknown-english` と `preferred-japanese`：語全体の大文字・小文字を区別せず同じ語として集約。複数の表記がある場合は `variants` に保存。
- `unquoted-identifier`：大文字・小文字を区別して集約。

いずれも、保存する出現例は候補ごとに最大20件とする。

一時データをすべて削除する場合は、対象リポジトリのルートで次を実行する。取得済みの技術辞書も削除されるため、次の検査時に再取得が必要になる。

```sh
pnpm --dir .agents/skills/japanese-proofreading textlint:clean --root ../../..
```
