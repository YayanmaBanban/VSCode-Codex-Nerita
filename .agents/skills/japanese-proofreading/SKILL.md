## 対象と実行方法

### 参照する校正ルール

対象に応じて、次の文書を読む。静的検査だけでなく、説明と実装の一致も確認する。

|校正する対象|参照先|
|----------------------------------------------------------------------|----------------------------------------------------------------|
|すべての対象|[校正ルール](references/Proofreading.md)|
|README・利用ガイド・SKILL.md・設計文書など|[Markdown 文書のルール](references/Markdown.md)も読む|
|README・利用ガイド・SKILL.md・仕様書など、章立てのある文書の文章と構成|[文章の校正](references/Prose.md)も読む|
|仕様書|通常の校正ルールに加えて[仕様書の校正](references/spec.md)も読む|

文章と構成の校正ルールを、コードコメント・UI 文言へ一律には適用しない。

### コード内の検査対象

対象の言語・形式に応じて、検査範囲と適用ルールを読む。

|対象の言語・形式|参照先|
|---|---|
|TypeScript / JavaScript（JSX を含む）|[TypeScript / JavaScript の検査](references/profiles/ts-js.md)|
|Svelte|[Svelte の検査](references/profiles/svelte.md)|

`textlint:review*` の実行時には、意味を確認するためのレビュー用データも出力する。
修正前に周辺コードと利用箇所を読み、人が読む文言か、機械が読む値かを確認する。

### 対象範囲とコマンドの選択

範囲の指定がなければ、未コミット変更を対象とする。
コミット済みの変更や特定の機能を校正する場合は、差分から対象ファイルを選び、引数で指定する。

|校正する範囲|実行手順|
|----------------------------------------|---------------------------------------------------|
|変更分|[変更ファイルのコマンド](references/Cmd-Changed.md)|
|Git の変更状態に関係なく、全体や指定範囲|[全体・指定範囲のコマンド](references/Cmd-All.md)|

`--changed` で対象を指定しなければ、HEAD との差分に含まれるファイルと未追跡ファイルを選ぶ。
変更行だけでなく、選択したファイル内の文章を抽出する。修正範囲は依頼と差分に照らして判断する。

## 実行準備とパスの指定

このスキルには、`private` を設定した Node.js パッケージが含まれる。
依存関係は本リポジトリの pnpm ワークスペースで管理する。
標準の設定では、ワークスペース全体の依存関係がインストール対象になる。

依存関係が未導入の場合は、リポジトリルートで次を実行する。

```sh
pnpm --dir .agents/skills/japanese-proofreading install
```

検査には、スキル内の `run.cmd` を使う。
第1引数に `package.json` のスクリプト名、続けて追加オプションや対象ファイル・フォルダを渡す。

```powershell
.\.agents\skills\japanese-proofreading\run.cmd textlint:changed docs/example.md
```

スキルは対象リポジトリの `.agents/skills/japanese-proofreading/` に配置する。
`run.cmd` が自身の配置からリポジトリルートを求め、`--dir` と `--root` を補う。
対象パスは、コマンドの実行場所にかかわらずリポジトリルートを基準に指定する。

## 設定と除外対象

文章用のルール・技術辞書の取得元・依存関係はスキル側から読み込む。
許可する英単語・推奨する日本語表記・レビューだけで扱う範囲は、対象リポジトリのルートに置く `.textlint-project.json` で管理する。
このファイルがなければ、用語の追加指定なしで、コメント以外の文言も静的に検査する。
対象固有の `.textlintignore` と `.textlint-cache/` も、対象リポジトリ側に配置する。

`.textlintignore` はルートと配下の各フォルダで有効とする。
パターンは配置先を基準に評価し、上位の設定を継承する。下位の設定を優先し、`!` で除外を解除できる。
ただし、除外したフォルダ内の設定は読み込まない。

- `.git/`・`node_modules/`・`.textlint-cache/` は常に検査から除外する。
- リポジトリ外のパスとシンボリックリンクは、検査対象に指定できない。

## 校正と完了

1. 選択した手順でレビュー用データを生成し、JSONL と検査結果を読む。終了コードだけでなく出力も確認し、文章への指摘と実行エラーを区別する。実行エラーは原因を解消してからレビューを進める。
2. JSONL の `file` と `startLine` を使い、元の文章と周辺コードを読む。識別子・固有名詞を機械的に翻訳せず、実際の処理を自然な日本語で説明する。
3. 指摘のない文章も依頼範囲で確認する。修正前後の意味・重要度・確実さ・文の役割を照合する。校正に合わせて製品の動作を変更しない。
4. 同じ対象を再検査する。変更ファイルの手順なら `textlint:changed`、全体・指定範囲の手順なら `textlint` を実行する。対応する古い指摘・レビュー用データも削除される。
5. 校正した範囲、修正内容、検査結果、未解決・未確認事項を簡潔に報告する。静的検査の成功だけで意味の確認を済ませたと扱わない。

校正は依頼時に実行する。通常の実装完了条件や `pnpm package` に、この手順を追加しない。

## 候補ファイルと一時データの扱い

### 指摘の集約

候補ファイル（`issues-changed.json` / `issues-all.json`）では、指摘の種類ごとに次の基準で集約する。

|指摘の種類|集約する基準|
|---------------------------------------|----------------------------------------------------------------------------------------------------------------|
|`unknown-english`・`preferred-japanese`|語全体の大文字・小文字を区別しない。複数の表記は `variants` に保存する|
|`unquoted-identifier`|大文字・小文字を区別する|
|`ai-slop-pattern`・`ai-slop`|種類・検出表現・診断メッセージで集約する。英字部分の大文字・小文字は区別せず、異なる表記は `variants` に保存する|

いずれも、保存する出現例は候補ごとに最大20件とする。

### レビュー時の確認

- `ai-slop-pattern` は、高確度の不自然な表現を示す。通常の静的検査も失敗させる。`suggestion` は置換文字列ではなく、具体化する対象の案内として読む。
- `ai-slop` は、文脈確認が必要な表現を示す。単独では静的検査を失敗させない。元ファイルと周辺コードを確認し、正当な用語なら維持する。

警告を消すこと自体を目的にせず、[校正ルール](references/Proofreading.md)に従って意味を確認する。

### 一時データの削除

プロジェクト側の検査結果とレビュー用データをすべて削除する場合は、対象リポジトリのルートで次を実行する。
スキル内の `config/technical-terms.json` に保存した技術辞書は保持する。

```powershell
.\.agents\skills\japanese-proofreading\run.cmd textlint:clean
```
