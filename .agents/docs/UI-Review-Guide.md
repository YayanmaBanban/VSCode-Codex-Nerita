# UI レビューの実行ガイド

Webview UI の表示・操作・アニメーションを変更する場合、または UI レビューを依頼された場合に参照する。テストの成功だけで完了とせず、生成画像を実際に開いて確認する。既存の対象シナリオがある場合は実行する。

文書のみの変更や表示・操作に影響しない内部整理では、UI レビューは不要。

## 現在の構成

- Story：`src/stories/**/*.stories.tsx`。実機側に対応する機能別の構成で、実コンポーネントの観察開始状態を作る。
- シナリオ：`tests/e2e/ui-review/*.spec.ts`。対象固有の操作・状態待ち・アサーションを記述する。
- 撮影・エラー収集：対象テストシナリオ内で Playwright の API を使用する。
- 実行設定：`tests/e2e/config/ui-review.config.ts`。実行ブラウザやビューポートは設定と対象テストシナリオを確認する。

対象はテストシナリオから確認する。シナリオ追加・実行環境を扱う場合は [実装ガイド](UI-Review-Implementation.md) を参照する。

## 変更前後の確認

1. 変更対象の実装・Story・テストシナリオを確認する。必要なら `pnpm storybook` で対象ストーリーを開き、現在の状態を確認する。
2. 既存 UI の変更では、比較に使う変更前の画像・結果を確保する。対象コードと条件の一致する保存済み結果がなければ、変更前の対象をレビューする。既存の失敗と変更由来の失敗を区別する。
3. 変更前の `dist/ui-review/test-results` と `dist/ui-review/report` をコピーして保存する。保存先は `dist/ui-review-history/<作業名>/before/` 配下とし、重複しない作業名を選ぶ。再実行で通常の出力先は置き換わる。ユーザーの既存成果物を上書きしない。
4. UI を変更し、再現する状態や操作が変わる場合はストーリーとシナリオを更新する。共有部品やテーマの変更では、利用側のシナリオも対象にする。
5. 対象をレビューする。広い範囲に影響する場合は全件実行する。
6. 変更後の画像を開き、変更前と比較する。文字の欠け・重なり・余白・位置・色・無効状態・フォーカスなど、対象の変更に関係する状態を確認する。操作の流れは動画も使って確認する。
7. console/page `error` と失敗したアサーションを確認する。不自然な表示や操作があれば修正し、影響するレビューを再実行して画像も確認する。
8. 実行したシナリオ、確認した状態、結果、成果物の場所、未確認事項を報告する。

対象シナリオがない場合は、変更する操作・状態を再現できるストーリーとシナリオを追加する。文言や装飾だけの変更など追加が不要な場合も、実画面または生成画像で確認し、方法と確認範囲を報告する。実行できない場合は代替の確認結果と未確認事項を示し、確認済みと扱わない。

```sh
pnpm ui-review
pnpm ui-review chat
pnpm ui-review tool-cards
pnpm ui-review:report
```

名前指定はテストシナリオのパスを絞り込む。実行結果の件数を確認し、対象が0件の実行を成功したレビューとして扱わない。Storybook は自動起動するが、ローカルでは6006番ポートに既存サーバーがあれば再利用するため、このプロジェクトの Storybook であることを確認する。

## 撮影と成果物

テストシナリオは `page.goto("/iframe.html?id=<Story ID>&viewMode=story")` で開始する。意味のある状態ごとに `page.screenshot()` と `info.attach()` で画像を残す。添付名は状態が分かる名前にする。クリック完了後を押下中と呼ばず、押下中の撮影ではマウスを押した状態を維持する。

フォント・画像の読み込み、メニューの表示や非同期処理の完了など、対象固有の待機はテストシナリオで行う。任意の固定時間待ちを共通処理へ追加して安定性を装わない。

- `dist/ui-review/test-results`：画像、動画、trace。
- `dist/ui-review/report`：画像・添付データ・動画・トレースを確認する HTML レポート。

console `error` と `page` `error` は対象テストシナリオで収集・検証する。画像・動画・トレースは成功時も保存する。PASS は見た目の品質保証を意味しない。

## アニメーションを変更する場合

`page.screenshot()` の撮影条件は対象テストシナリオで確認する。`animations: "disabled"` の指定は、任意の `JavaScript/Motion` アニメーションの時間制御ではない。

アニメーション自体を変更する場合は、動画だけで判断しない。再現可能な時間制御または対象固有の検証方法を用意できる場合に、次の状態を画像で確認し、撮影時刻・条件を記録する。

- initial：開始前
- early：動き始め
- middle：途中
- late：完了直前
- completed：完了後

通常の `page.screenshot()`に固定時間待ちを足しただけで、正確な中間フレームを撮影できたと判断しない。中間状態を確認できない場合は、確認済みの始点・終点・動画と、未確認の中間状態を分けて報告する。今回の変更に時間別撮影が必要なら専用の方法を追加し、既存の静止画レビューと分離する。

## 性能問題を調査する場合

描画の引っかかりや入力遅延など、性能問題が疑われる場合は、利用可能なら Chrome DevTools の Performance 記録などで計測する。Chrome DevTools MCP は利用可能な場合の選択肢であり、必須ツールではない。

Playwright のトレースは操作・DOM・通信などの調査用で、ブラウザーの Performance トレースの代替にはしない。実行環境と再現操作を揃え、長い処理やレイアウト・描画の負荷を確認する。計測手段がない場合は代替の観測方法と限界を報告し、見た目だけから性能改善を断定しない。
