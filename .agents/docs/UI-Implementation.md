# Webview UI の実装

Webview UI を作成する際に参照します。既存のコンポーネント・テーマ・スタイルの構成を確認し、画面全体で表示と操作が揃うように実装してください。

## スタイルの選択

- Tailwind CSS を配置・余白・文字サイズ・色・枠線などの通常のスタイルに使用する。
- 色は既存のテーマ定義を利用し、VSCode のテーマ変数への追従を維持する。同じ用途の色や寸法は、既存の指定に合わせる。
- Tailwind のクラス名は完全な文字列で記述し、文字列の組み立てによって生成対象から漏れないようにする。
- 共通の基本スタイルや複雑なアニメーションなど、CSS でまとめた方が意図を読み取りやすい処理は CSS に残してよい。
- 既存 CSS から移行する場合は、重複する宣言とスタイルの優先順位を確認する。Tailwind の使用だけを理由に、見た目や操作を変更しない。

## 実装時の確認

- 既存の UI コンポーネントや操作パターンを利用し、キーボード操作・フォーカス・無効状態を保つ。
- 狭い幅、長い文言、明暗テーマでも表示と操作が成立するようにする。
- 実機用の UI と Storybook 専用のモック・サンプルデータを分ける。
- Storybook での表示・操作の確認と、Extension Host や実際の `CodexAppServer` 接続の検証は分ける。

### JSX / Tailwind CSS の可読性

- 短い静的な `className` はそのまま記述する。
- Tailwind CSS のクラスが長くなり読みづらい場合は、意味のあるまとまりに分けて可読性を優先する。
- 条件付きクラス、動的クラス、または外部 `className` との結合には `cnfast` の `cn()` を使う。
- `cn()` 内では 1 クラスずつ分割せず、レイアウト・サイズ・見た目・状態など関連する Tailwind CSS のクラスをまとめる。
- JSX が大きくなった場合は、コメントで区切るより意味のある UI 単位をコンポーネントへ分割する。
- 行数だけを理由に、小さな JSX を過剰にコンポーネント化しない。
- 既存コンポーネントに明確なスタイルがある場合は、その周辺の書き方を優先する。

`cn()` は `cnfast` からインポートする。

```ts
import { cn } from "cnfast";
```
