# Webview UI の実装

Webview UI を作成する際に参照します。既存のコンポーネント・テーマ・スタイルの構成を確認し、画面全体で表示と操作が揃うように実装してください。

## スタイルの選択

- Tailwind CSS を配置・余白・文字サイズ・色・枠線などの通常のスタイルに使用する。
- 色は既存のテーマ定義を利用し、VS Code のテーマ変数への追従を維持する。同じ用途の色や寸法は、既存の指定に合わせる。
- Tailwind のクラス名は完全な文字列で記述し、文字列の組み立てによって生成対象から漏れないようにする。
- 共通の基本スタイルや複雑なアニメーションなど、CSS でまとめた方が意図を読み取りやすい処理は CSS に残してよい。
- 既存 CSS から移行する場合は、重複する宣言とスタイルの優先順位を確認する。Tailwind の使用だけを理由に、見た目や操作を変更しない。

## 実装時の確認

- 既存の UI コンポーネントや操作パターンを利用し、キーボード操作・フォーカス・無効状態を保つ。
- 狭い幅、長い文言、明暗テーマでも表示と操作が成立するようにする。
- 実機用の UI と Storybook 専用のモック・サンプルデータを分ける。配置は [ディレクトリ構成](Directory-Structure.md) に従う。
- 表示・操作の確認は [UI レビュー](UI-Review-Guide.md) に従う。Storybook での確認と、Extension Host や実際の Codex App Server 接続の検証は分ける。

### JSX の可読性

長い `className` は1行の長さだけを理由に手動改行せず、
`cn()` などを使ってレイアウト・外観・状態・レスポンシブ指定など
意味のまとまりごとに分ける。

JSX が大きくなった場合はコメントで区切るより、
意味のある UI 単位をコンポーネントへ分割する。
