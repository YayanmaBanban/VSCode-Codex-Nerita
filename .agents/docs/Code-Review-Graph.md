# コード調査・レビューと依存グラフ

複数ファイルの依存関係、変更影響、構造の調査に使うガイドです。対象が明確な局所修正や文書のみの変更では、対象ファイルや差分を直接確認できます。

## 調査手段の選択

- ファイルやシンボルが分かっている場合は、対象と利用側を直接読む。検索は `rg` / `rg --files` で範囲を絞る。
- 機能をまたぐ依存調査、大規模な移動、未知の構造の把握では、利用可能なら `code-review-graph` MCP を優先して調査範囲を絞る。
- 必要な情報が得られたら実コードの確認へ進む。すべてのグラフツールを順に呼ぶ必要はない。

## グラフを使う場合の目安

| 確認したいこと | ツールの候補 |
| --- | --- |
| 関連するコード・シンボル | `semantic_search_nodes_tool`、`query_graph_tool` |
| インポート元・利用側・関連テスト | `query_graph_tool` |
| 全体構造・機能間の結び付き | `get_architecture_overview_tool` |
| 差分の影響とレビューの優先箇所 | `detect_changes_tool` |
| 特定ファイルの影響範囲・実行経路 | `get_impact_radius_tool`、`get_affected_flows_tool` |
| 差分に関する追加の実装文脈 | 必要に応じて `get_review_context_tool` |
| 改名・構造改善の候補 | `refactor_tool` |

引数と利用可能な操作は、その時点のツール定義を確認してください。差分の比較元は依頼対象に合わせ、未コミット変更なら `HEAD`、PR レビューなら対象ブランチとの比較などを明示します。

## 結果の扱いと代替手段

- グラフの更新日時・対象リポジトリ・コミットと、現在の作業ツリーを照合する。未コミットの移動や新規ファイルはグラフに未反映の場合がある。
- MCP が使えない、古い、結果が空、対象言語や参照を十分に扱えない場合は、`git diff`・`rg`・実ファイルの確認で進める。グラフの利用可否だけで作業を止めない。
- グラフと実コードが異なる場合は実コードを正とする。「参照なし」「未使用」という候補だけで削除を判断せず、動的インポート・設定・エントリーポイントも確認する。
- 実装や指摘は、対象コード・利用側・関連テストで裏付ける。グラフのリスクスコアだけで正しさを判断しない。

## レビューの完了条件

不具合の指摘には、該当箇所、起きる条件、影響を示します。確認できた事実と推測を区別し、実行した検証と残る未確認事項を報告してください。追加調査や再検証は、変更・失敗・未解決の懸念がある範囲で行います。
