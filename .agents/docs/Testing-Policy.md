# テスト方針

テストの追加・変更・整理に適用する。目的は、少ない変更コストで製品の振る舞い・契約・安全性の回帰を検出すること。件数やカバレッジの増減を成果としない。

## 追加・維持の判断

「このテストがなければ、どの具体的な不具合を見逃すか」で判断する。
対象仕様の既存テストを確認し、同じ回帰を検出できるなら既存の担当テストを使う。
担当テストは、その仕様を直接検証するテストまたはテスト群を指す。

- 追加する: 未保護の重要なユーザー動作、外部契約、安全境界、複雑な状態遷移、実際に起きた不具合の再発防止。
- 既存の担当テストを拡張する: 同じ仕様の境界値や固有の失敗経路。代表値・境界値・過去の回帰を選ぶ。
- 削除・統合する: 固有の回帰を説明できない重複、外部挙動を変えないリファクタだけで壊れるアサーション。

新しい実装やファイルに対応するという理由だけでは、テストを追加しない。
局所修正では関連するテストを調べればよく、全スイートの監査を毎回行う必要はない。

## 一時検証と継続するテストの配置

実装中の動作確認や不具合の一時的な再現には `tests/scratch/` を使う。UI 操作スクリプトも対象とする。Git 管理に含めるが、通常のテスト実行・CI・Storybook の自動収集からは除外し、必要なファイルを明示して実行する。各検証には目的と実行方法を残す。確認が終わったものや用途を失ったものは削除してよく、恒久的な保守や代わりのテストの追加を求めない。

継続して製品の回帰を検出するテストは、`tests/scratch/` 以外の正式な配置に置く。対象は `tests/product/`、`tests/vscode/`、`apps/nerita-ui/stories/` など。追加時には、守る具体的な不具合と実行タイミング・コマンドを明確にする。一時検証を作ったことだけを理由に正式な配置へ移さない。共通の補助コードは `tests/support/` などに置き、利用するテストとともに維持・整理する。

正式なテストは件数削減や実装完了だけを理由に削除しない。不要になった仕様や重複を整理する場合は、保護が不要になった理由、または保護を引き継ぐ担当テストを確認する。配置だけで維持する価値や削除禁止を決めない。

## 仕様の担当テストとレイヤー

1仕様につき原則1つの担当テストを置く。上位層には、接続や実環境でしか検出できない失敗を担当させる。

| 種別 | 主な責任 |
| --- | --- |
| 単体テスト | ロジック、変換、状態遷移の入力と結果 |
| 契約テスト | スキーマ、プロトコル、公開 API、設定・保存形式の境界 |
| 結合テスト | コンポーネント間の接続、実 SDK、保存と独立した再起動後の復元 |
| スモークテスト | 起動・主要機能・配布物が実環境で動くこと |
| e2e / UI | 重要なユーザー操作と表示結果 |

正確な保存パスは保存先の契約テストで検証する。永続化やスモークテストでは保存・再起動・復元を検証し、パス文字列を重ねて固定しない。
Storybook の描画成功は、Extension Host や実バックエンドとの接続成功を意味しない。

## アサーションと検証データ

入力と観測可能な結果を優先する。内部クラス・インポート・ファイル分割・中間構造・DOM の入れ子・細かな呼出順や回数は、それ自体が契約の場合だけ固定する。
二重実行や承認迂回を検出する呼出回数は、安全性を守るアサーションとして扱う。

検証データやヘルパーは、準備・後片付け・外部境界のモック・ユーザー操作に使う。
期待値を求めるために本番の判定アルゴリズムを複製しない。
テスト専用の不要なエクスポートや抽象化を本番コードに追加しない。

## UI テストの実装

追加・維持・一時検証の判断には、前述の共通方針を適用する。画像の比較やアニメーションなど、見た目の確認手順は [UI レビューの実行ガイド](UI-Review-Guide.md) を参照する。

### Storybook の通信境界

設定は `apps/nerita-ui/vitest.config.ts`、ストーリーは `apps/nerita-ui/stories/` に置く。表示用データは `apps/nerita-ui/stories/chat/fixtures/` に置く。

`createStoryBridge()` の `sent` で送信を記録し、`emit()` と `patchState()` で検証側が指定する Host 応答を配信する。

1. 実 UI を操作する。
2. 送信記録の種類・識別子・入力内容を確認する。
3. 固定の Host 応答を注入する。
4. 応答後の表示と操作可否を確認する。

承認後の完了状態を注入しても、実行許可の正しさを検証したことにはならない。共通ブリッジで、承認判断・認証・保存・バックエンド切替などの製品処理を再実装しない。送信された選択肢や識別子を補正しない。

表示デモの編集バッファと、本番の保存・信頼判定を区別する。非同期処理は応答前・成功後・失敗後の必要な状態を明示し、即時成功だけで受付待ちを隠さない。

### 実 Webview の受入

シナリオは `tests/vscode/webview.cjs` と `tests/vscode/account.cjs` に置く。起動は `config/test-distribution.cjs` と `config/test-webview.cjs` が担当する。

本番の状態を直接書き換えず、画面操作と公開コマンドを使う。モデル応答はローカル HTTP で代替する。承認前の未作成、承認後の本文、停止後の未作成など、表示以外の観測を持つ。

VS Code の拡張テストモードは確認ダイアログを禁止するため、通常の開発 Host と一時的な補助拡張で実行する。専用プロファイルでは確認ダイアログを `custom` に設定する。利用者の拡張機能や設定へインストールしない。

生成物・一時領域・プロセスを実行ごとに分離し、準備失敗や結果ファイルの未生成を成功扱いにしない。検証終了と期限切れでは専用プロセスを回収する。要素の役割や名前で操作し、対象の状態が成立するまで待つ。

## 安全性・データ保持

サンドボックス・承認・信頼・ワークスペース外アクセス・シェル・シンボリックリンク・外部コード読込みは、許可と拒否の両方を検証する。
破損したセッションの読込み、復元失敗、会話の分岐では、既存データや現在の会話を失わないことを守る。
これらのテストを削除・統合するときは、保護していた失敗経路を引き継ぐ担当テストを確認する。
SDK の配線、OS の境界、人の承認操作など、異なる境界を検証する複数レイヤーは維持する。
初期化失敗や前段の拒否を、目的の安全境界が機能した証拠にしない。

## 検証と完了

変更の影響に合うテストから実行し、今回の変更による失敗を修正して関連テストを再実行する。
ユーザーが依頼した範囲で、一時検証データだけを使うローカル検証は、その都度の確認を挟まず進める。
実認証・外部サービス・インストールを伴う試験は、必要な環境と依頼の範囲を確認して選ぶ。
日常のローカル検証は `pnpm test:local`、担当を選ぶ場合は `pnpm test:product <ファイル名の一部>` を使う。
`pnpm test:regressions` は通常版の成功と、狙った実装破壊によるアサーション失敗を確認する。
`pnpm test:distribution` は今回生成した VSIX を展開し、同梱 SDK と実 Extension Host を検証する。
`pnpm test:windows` は新規 VSIX の Codex を使い、実 Windows サンドボックスの書込み境界と停止時の子孫プロセス回収を検証する。準備済みの elevated サンドボックスと既存の `CODEX_HOME` を使用し、未準備を成功扱いにしない。新規作業領域だけを書込み対象にする。
`pnpm test:webview` は新規 VSIX と専用プロファイルで、実 Webview の信頼操作・再接続・承認・停止・認証取消し・設定切替・履歴復元を検証する。モデルの HTTP 応答だけを代替し、画面操作の結果を実ファイルでも確認する。明暗テーマと狭幅の適用値、画像とトレースは実行ごとに保存する。
`pnpm test:external` は導入済み Pi 拡張の受入検証に使う。導入先は `NERITA_EXTERNAL_AGENT_DIR`、`PI_CODING_AGENT_DIR`、ホーム内の `.pi/agent` の順で選ぶ。Web 拡張の検証には公開 GitHub リポジトリの取得を伴い、未導入・通信失敗を成功扱いにしない。
Storybook の表示・操作は `pnpm test:storybook` で別に実行する。ローカル検証の成功を、実 UI・OS・外部サービスの受入へ読み替えない。

失敗は、製品の回帰、意図した仕様変更、実装への過剰な結合、環境不足に分けて判断する。
成功させるためだけにアサーションを弱めたり、スキップへ変更したりしない。
必要な検証が通ったら完了とし、新たな変更・失敗・未解決の懸念がなければ実行範囲を広げない。
全件実行は、全体整理や共通基盤の変更などで必要な場合、または明示的に依頼された場合に行う。
報告には変更理由、実行結果、残る失敗・未検証範囲を含める。
