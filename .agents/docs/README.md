# 指示ファイルの保守

`AGENTS.md`・このディレクトリ・プロジェクト独自スキルを見直すときの方針です。通常の実装時に毎回読む必要はありません。

## 情報の置き場所

| 場所 | 内容 |
| --- | --- |
| ルートの `AGENTS.md` | リポジトリ共通の規約、重要な境界、作業別の参照先 |
| `.agents/docs/` | 特定の作業で必要になる判断基準や検証方法 |
| `.agents/templates/` | 指示文書の校正依頼に使う共通方針と技術別の確認項目 |
| `.agents/skills/` | 明確な用途を持つ再利用可能な作業手順と補助資産 |
| アプリやテストの README | 利用者向けの説明、集約したガイドへの入口 |

既存のガイドは [配置](Directory-Structure.md)、[コード調査](Code-Review-Graph.md)、[UI 実装](UI-Implementation.md)、[UI レビュー](UI-Review-Guide.md) に分けています。

UI レビューの詳細もこのディレクトリ内にまとめています。

- [実装・実行ガイド](UI-Review-Implementation.md)：シナリオ追加、撮影と成果物の扱い

## 他プロジェクトへのコピー

ルートの `AGENTS.md` と `.agents/docs/` を同じ相対配置でコピーし、移植先のプロジェクトに合わせて調整してください。ガイドから参照する詳細文書はこのディレクトリ内に集約しています。

校正テンプレートも使う場合は `.agents/templates/` を同じ相対配置でコピーしてください。

調整する対象は、ソースの配置、使用フレームワーク、コマンド、テスト環境、利用可能な MCP・スキルです。Extension Host の境界など、移植先に存在しない機能の指示は削除または置き換えてください。元文書の対象領域も見直し、配置・分割などの共通基準は移植先の主要領域へ適用し、実行環境固有の規則は適用先を限定してください。

この文書一式に Storybook 拡張・Playwright のフィクスチャ・CI・スキル本体は含まれません。コードパスやコマンドは本プロジェクトの例として扱い、移植先の実装へ対応付けてください。ライブラリ由来のスキルは別途管理します。

## 更新時の判断

- 指示の適用条件を具体的に書く。局所修正にも全資料の読み込みや全ツールの利用を要求しない。
- プロジェクト固有の制約と完了条件を残し、同じ説明の重複や不要な実行順序を減らす。
- ツールが利用できない場合の代替手段と、未確認になる範囲を明記する。
- 変化しやすいシナリオ数・詳細な API 仕様は複製せず、実ファイルやツール定義を参照する。
- スキルの `description` は用途と発動条件を短く示す。複数の独立した手順がある場合は、必要な詳細だけ読める構成にする。
- ライブラリ由来の `motion` スキルは、リポジトリの指示整理から分離し、提供元の更新と合わせて管理する。
- 文書修正、単一ファイル修正、機能間の移動、UI 変更、MCP 利用不可の例で、必要な資料・確認にたどり着けるか点検する。

文書の整合性確認と実タスクでの効果検証は区別します。指示を短くしただけで品質や速度が改善したとは判断せず、以後の作業で不要な読み込み・重複検証・確認漏れが減るか確認してください。

## 公開資料

OpenAI は、作業に応じた資料の参照、スキルの明確な発動条件、過剰な手順の見直しを勧めています。このリポジトリでは上記の方針として適用します。MCP の使い分けなどの個別ルールはプロジェクト側の判断です。

- [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
- [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

作業に必要なルールはリポジトリ内で完結させ、非公開ページへのアクセスを前提にしません。

## プロジェクトにあわせて校正する場合

[共通方針](../templates/adapt-base.md)と、実際に使用する技術のプロファイルを指定してください。プロファイルは組み合わせ可能で、[React](../templates/profiles/react.md)は React を使用する領域、[VS Code 拡張](../templates/profiles/vscode-extension.md)は拡張機能の責務境界に適用します。対応プロファイルがない技術も共通方針で確認します。

本プロジェクトでの依頼例です。

```text
.agents/templates/adapt-base.md の方針で、
AGENTS.md と .agents/docs/ を本プロジェクト向けに校正してください。
このプロジェクトはReact製Webviewを持つVS Code拡張なので、
.agents/templates/profiles/vscode-extension.md と
.agents/templates/profiles/react.md の確認項目も適用してください。
Reactの規則はWebviewに限定し、配置・分割などの共通基準は
Extension Host・Webview・共有コードの各主要領域について確認してください。
```

# テンプレートを追加したい場合

以下の依頼例では、技術名・出力ファイル名・重点的に確認したい境界を差し替えてください。

Unreal Engine 用のテンプレートを追加する依頼例です。

```text
.agents/templates/profiles/ に Unreal Engine（UE/C++）用の
unreal.md を追加してください。

adapt-base.md の共通方針と、既存プロファイルの見出し・記述粒度に合わせてください。
推奨フォルダ構成ではなく、実際の構成を確認する観点として記述してください。

特に以下を確認対象にしてください。
- Runtime / Editor / Developer の役割とビルド対象
- Project / Plugins / Modules の責務・依存関係
- C++ / Blueprint の役割分担
- モジュールをまたぐ公開API・共有コードの配置
- Editor内の確認と、パッケージ化した実行環境での検証の違い

存在しない領域の作成は要求せず、採用されているものだけに適用してください。
共通方針の重複や、網羅的なAPI・コマンド一覧は追加しないでください。
技術固有の内容は公式資料で確認してください。

変更対象はテンプレートと、その利用案内のみです。
本プロジェクト自体にUEの規則を適用する作業は行わないでください。
```
