# 指示ファイルの保守

`AGENTS.md`・このディレクトリ・プロジェクト独自スキルを見直すときの方針です。通常の実装時に毎回読む必要はありません。

## 情報の置き場所

| 場所 | 内容 |
| --- | --- |
| ルートの `AGENTS.md` | リポジトリ共通の規約、重要な境界、作業別の参照先 |
| `.agents/docs/` | 特定の作業で必要になる判断基準や検証方法 |
| プロジェクト独自スキルを追加する場合 | 明確な用途を持つ再利用可能な作業手順と補助資産。存在するスキルだけ参照する |
| ルートの `README.md` | 利用者向けの説明、実行コマンド、配置の案内 |

既存のガイドは [配置](Directory-Structure.md)、[コード調査](Code-Review-Graph.md)、[UIレビュー](UI-Review-Guide.md) に分けています。VS Code拡張機能の実装は `src/extension/`、開発ツール設定は `config/`、テストは `tests/` を基準に確認します。

UIレビューの詳細もこのディレクトリ内にまとめています。

- [実装・実行ガイド](UI-Review-Implementation.md)：Storyとspecの対応、操作・撮影、起動設定、CI追加時の確認

## 他プロジェクトへのコピー

ルートの `AGENTS.md` と `.agents/docs/` を同じ相対配置でコピーし、移植先のプロジェクトに合わせて調整してください。ガイドから参照する詳細文書はこのディレクトリ内に集約しています。

調整する対象は、ソースの配置、使用フレームワーク、コマンド、テスト環境、利用可能なMCP・スキルです。移植先に存在しない機能の指示は削除または置き換えてください。

文書をコピーしても実装は導入されません。コードパスやコマンドは移植先の実ファイルと照合し、導入済みの設定、未実装の機能、参照不整合を区別してください。ライブラリ由来のスキルは別途管理します。

## 更新時の判断

- 指示の適用条件を具体的に書く。局所修正にも全資料の読み込みや全ツールの利用を要求しない。
- プロジェクト固有の制約と完了条件を残し、同じ説明の重複や不要な実行順序を減らす。
- ツールが利用できない場合の代替手段と、未確認になる範囲を明記する。
- 変化しやすいシナリオ数・詳細なAPI仕様は複製せず、実ファイルやツール定義を参照する。
- スキルのdescriptionは用途と発動条件を短く示す。複数の独立した手順がある場合は、必要な詳細だけ読める構成にする。
- 文書修正、単一ファイル修正、機能間の移動、UI変更、MCP利用不可の例で、必要な資料・確認にたどり着けるか点検する。

文書の整合性確認と実タスクでの効果検証は区別します。指示を短くしただけで品質や速度が改善したとは判断せず、以後の作業で不要な読み込み・重複検証・確認漏れが減るか確認してください。
