# 指示文書をプロジェクトへ適合する共通方針

`AGENTS.md` と `.agents/docs/` を移植先のプロジェクト向けに校正するときに使用します。通常の実装時に毎回読む必要はありません。変更対象は文書のみです。

## 適用する資料

この共通方針と、実際に使用している技術に対応する `profiles/` の確認項目を適用してください。複数のプロファイルを組み合わせる場合は、それぞれの適用領域を明確にします。React製Webviewを持つVS Code拡張では、VS Code拡張のプロファイルに加え、WebviewへReactのプロファイルを適用します。

プロファイルは確認観点であり、推奨ディレクトリ構成や機能の追加要求ではありません。対応するプロファイルがない場合も、以下の共通方針で実装・設定から必要な境界を確認してください。

## 校正の方針

- 元文書の目的・見出し構成・記述粒度をできるだけ維持し、最小限の差分で適合する。
- プロジェクト固有のパス、コマンド、技術名、実行・ビルド・テスト環境は、実ファイルと設定に合わせて置き換える。適用されない項目は削除し、共通の判断基準は残す。
- 元文書の対象範囲は維持対象としない。共通の設計判断は移植先の主要領域へ適用し、実行環境固有の規則は該当領域に限定する。見出しの維持によって必要な領域が欠落する場合は、最小限の変更で調整する。
- プロファイルに列挙された領域が実在するか確認する。存在しない領域の作成や、文書に合わせたコード・ディレクトリ構成の変更は行わない。
- 現状の調査結果、不具合一覧、未実装機能、将来の構成提案は指示ファイルに追加せず、必要なら作業結果として別途報告する。網羅的なファイル一覧・コマンド一覧へ拡張しない。

## 対象範囲と境界の確認

実装・設定と既存文書を照合し、次の判断基準が文書化されているか確認してください。実行環境、共有コード、テストは区別して扱います。

| 観点 | 確認内容 |
| --- | --- |
| 実行環境 | 主要な処理がどこで動作し、どのAPIに依存できるか。ビルド・配布の境界はどこか |
| 配置・分割 | 各主要領域に配置・分割・共通化の判断基準があるか。元文書が一方の領域だけを対象にしていないか |
| 共有・通信 | 領域をまたぐ契約・共有コードの置き場所、依存方向、通信境界が明確か |
| 検証 | 各テストが何を検証し、何を代替できないか。実環境とモックの違いが明確か |

共通基準は領域ごとに重複記載せず、共通の適用範囲と領域固有の例外を示してください。名称や技術の一般論だけで判断せず、実際の利用側・エントリーポイント・設定を根拠にします。

## 完了時の確認と報告

文書内の参照先・パス・コマンドを照合し、適用範囲の抜けやプロファイル間の矛盾がないか確認してください。文書のみの変更に無関係なビルドやUIレビューは要求しません。確認できない前提は断定せず、未確認事項として報告します。

完了後は、次の点を簡潔に示してください。

- 置き換え・削除した点
- 元文書から対象範囲を拡張した点
- プロジェクト固有の事情から追加が必要だった点
- 実施した確認と残る未確認事項
