# React の確認項目

[共通方針](../adapt-base.md)と併用し、React を使用する領域にだけ適用します。以下の名称は確認観点であり、同名のフォルダ作成を要求しません。

## 実行環境

- React の描画先と起動点を確認する。ブラウザ、Webview、サーバー側レンダリングなど、実際に存在する環境を区別する。
- React を含むアプリに別の実行環境がある場合は、その領域も共通方針や対応プロファイルで確認する。React の配置規則を Host やバックエンドへ機械的に適用しない。

## 配置・分割

- Component・Hook・状態管理・機能・ルートの責務と、機能内に置くもの・共通化するものの判断基準があるか確認する。
- `components`・`hooks`・`features`・`routes`・`shared` などの名前は実際の構成へ対応付ける。ルーティングなど採用していない仕組みの規則は追加しない。
- UI 固有の規則と、責務に沿った分割・変更理由による共通化などの共通基準が混同されていないか確認する。

## 共有・通信

- UI 内の共通部品と、サーバーや Host との共有契約を区別し、それぞれの配置先・依存方向を確認する。
- 外部 API や Host との通信窓口を明確にする。共有コードへ DOM や実行環境専用 API の依存を混入させない基準も確認する。

## 検証

- 単体テスト、Component・フックのテスト、UI レビュー、実環境の結合テストのうち、実際に存在する検証手段と確認範囲を確認する。
- Storybook などのモック環境での確認を、バックエンドや Host との実接続の検証として扱っていないか確認する。
