# VS Code拡張の確認項目

[共通方針](../adapt-base.md)と併用します。Extension Host・Webview・共有契約の責務境界を確認し、実在する領域へ適用してください。Webviewや共有専用フォルダの新設は要求しません。Reactを使用するWebviewには[Reactの確認項目](react.md)も適用します。

## 実行環境

- 拡張機能のエントリーポイントと設定から、ローカル・RemoteのNode.js Extension Host、Web拡張の実行環境など、実際の対応範囲を確認する。
- Webviewがある場合はHostとは別の実行環境として扱い、利用できるAPIと通信方法を確認する。
- 外部プロセス・同梱実行資産がある場合は起動側と配布対象OS・アーキテクチャを確認する。開発用Node.jsとHostの実行環境を混同しない。

## 配置・分割

- Host側の起動・VS Code連携・状態管理・外部通信と、Webview側のUI・状態管理に、それぞれ必要な配置・分割の判断基準があるか確認する。
- 元文書がWebviewだけを対象としていないか確認し、責務による分割や共通化などの共通基準をHostと共有コードにも適用する。Component・HookなどReact固有の分類はHostへ適用しない。
- 実際のディレクトリ名へ対応付ける。`src/extension/`・`src/webview/`・`src/shared/` という構成自体は要求しない。

## 共有・通信

- HostとWebviewのメッセージ契約・受信データの検証・通信窓口の配置を確認する。WebviewからHost実装やNode.js専用APIを直接利用する規則になっていないか確認する。
- 共有コードがある場合は、HostとWebviewの実装から独立し、双方で利用できる依存に限定されているか確認する。共有専用フォルダがなくても契約の管理場所を確認する。
- UI内・Host内だけの共通処理と、境界をまたぐ共有契約を区別する。`shared` は独立した実行環境ではなく、共有責務を持つ領域として扱う。

## 検証

- Host・共有処理の単体テスト、VS Code上の結合テスト、WebviewのUI確認について、実際の検証手段と確認範囲を確認する。テストコードは実行対象と実行環境を区別して配置を判断する。
- Mock、BridgeやStorybookの確認が、VS Code API・実際のメッセージ通信・外部プロセス接続の検証を代替すると記述していないか確認する。
